# UI in Figma: fundamentals every style book uses

## 1. When this skill starts
`ui-design` drives the stages (moment, decision record, flow sheet, states, wireframe options, grey value pass, rule sheet, target image). This skill is how each is built in Figma: the flow and wireframe pages first (steps 1-3), then, once the target image is approved, tokens, components and screens (steps 4-10), built cleanly so the result looks pro **and** survives the trip into Roblox. Core principles: `ui-design` SKILL §7; the self-review lines S-xx: `ui-design/references/review.md` §6. After a context compaction, re-read §3, §5 and §6 of this file before continuing.

## 3. Steps
1. **File.** One Figma file per game UI; pages `Flow`, `Wireframes`, `Refs`, `Components`, `HUD`, `Menus`, `Shop`, `Popups`. Frame **1920 × 1080** ("Presentation" preset) per screen (TC@1:00, TS@1:00, TP@0:13), plus a phone layout frame where the layout must change for phones: also 1920 × 1080 canvas, holding the `@ViewportDisplaySizeSmall` arrangement (a different arrangement, never a resampled copy; the 565 × 318 resample is the phone-fit view for reading checks, `ui-design/references/screen-contract.md` §5).
2. **Context background.** Behind every screen, a real game screenshot with a layer blur (TS@2:07), the busiest and brightest one available, or, for dark styles, a dark textured board with a vignette (TP@0:45). A new game without screenshots: a generated backdrop (counts against the image budget) or a flat mid-tone scene colour. Lock it. Never judge a UI on white.
3. **Flow and wireframes.** On `Flow`, one frame per step with the tap count; on `Wireframes`, the 2-3 grey options side by side at phone fit (the contact sheet for S-08), then the picked one as the **grey frame**: greys only, real content, the read order tuned (`ui-design` SKILL §3 steps 3-6). The grey frame's boxes are the layout the style keeps: styling may change looks, not positions or sizes, after the wireframe gate.
4. **Tokens first.** Colour styles or variables per role from the rule sheet (primary, positive, danger, utility, currency, each rarity), one corner radius, one outline weight, one text-stroke ladder, one spacing set. Values come from the style book.
5. **Build components, not copies.** Each control is a component with variants for its states (§4 F-15). The tutorials duplicate groups; components keep 30 buttons consistent when one changes.
6. **Compose the screen** from component instances over the grey frame's layout, using auto layout for rows, grids and lists.
7. **Check** with numbers first (`ui-design/references/review.md` §6 S-16 to S-30: read order kept, contrast, colour roles, phone view, icons, side by side with the target image), padding (F-13), every state, longest text; images only for failures and key screens.
8. **Motion** (optional prototype, `references/figma-mcp.md` §6): the rows from the game's motion table; frames for timing come from `export_video`.
9. **Mark each layer native / baked / tiled / library** (`references/roblox-handoff.md`, `references/effect-assets.md`) and export the baked parts.
10. **Hand off**: spec, Figma link + node ids, screenshots, exports (handoff §4).

## 4. Craft core (the techniques; origin → which style books use it)
| ID | Technique | How (Figma) | Values seen | Used by |
| --- | --- | --- | --- | --- |
| F-01 | **Navigation and selection** | Space+drag pan, Ctrl+scroll zoom; Ctrl+click selects a layer inside a group; Ctrl+Shift+click adds inner layers; Shift+click range in the layers panel; Alt+drag duplicates; Shift+Alt resizes from the centre keeping ratio; Ctrl+D then a move, and the next Ctrl+D repeats the offset; Enter on an image fill edits its crop; lock big frames so a marquee drag selects only buttons | TC@19:21, TS@8:16, TS@9:09, TC@17:44, TS@27:52, TS@58:42 | all |
| F-02 | **Name and group everything** | Ctrl+G, double-click to rename. Inside a control use fixed names: `face`, `lip`, `outline`, `halo`, `mask`, `fx` (highlights, textures), `icon`, `label`, `label-depth` | TS-T09, TC layer names | all |
| F-03 | **Depth block** (the chunky 3D control) | `face`: shape with a vertical 2-stop gradient, light top → darker bottom (rotate the gradient if it runs left→right). The two stops must differ clearly: **≥ 20 points of lightness (L\*)** between top and bottom, and the bottom is the saturated mid-tone of the hue, not a paler tint (PROPOSAL from the G2 owner review: a 12-point step on a pale blue card read as flat; tutorial buttons step ~20). Shift the bottom stop's hue toward a darker neighbour and keep its saturation, never mix in black or grey; gold goes warm orange-brown (`ui-design/references/style-choice.md` §6). Check the face in grayscale: top and bottom must look different. `lip`: Ctrl+D the face, move it down N px, Fill → Solid, darker shade of the face (darker than the gradient's bottom stop). Lip depth equal on every control of a size | lip 7 px on small TS buttons (TS@1:00:59); "a couple" of px in TC | cartoon, stud, anime (subtle) |
| F-04 | **Silhouette outline** around face + lip | Rounded rects: an `outline` rectangle behind, same radius, sized to cover face + lip, Outside stroke, no fill (this resizes cleanly and maps to a Roblox Frame + UIStroke); give face, lip, outline, halo and fx `STRETCH` constraints so the component resizes without rebuilding. Custom shapes: select face + lip, Ctrl+D, Flatten (Ctrl+E), move to the bottom, delete the fill, stroke Outside. A flattened outline does **not** resize well: rebuild it after resizing (TC@25:51) | 3 px black (TC), 5 px (TS) | cartoon, stud |
| F-05 | **Halo** (second outline ring) | Duplicate the outline below it, white, about 2× the weight, so a white ring shows outside the black line; soft drop shadow (Y 0) on the halo lifts the card off the panel. Figma's extra strokes on one layer share its weight and position (TC: the colours blend), so use two layers | black 3 + white 6 (TC@11:45) | cartoon; stud panels optional |
| F-06 | **Rim stroke** (inner light edge) | On `face`: stroke **Inside**, a brighter tint of the face colour | 4 px (TC@38:22, TS@12:02); 3-5 seen | cartoon, stud, anime |
| F-07 | **Group mask for highlights and texture** | Ctrl+D the face, Ctrl+G, right-click the inner copy → Use as mask; everything put in that group clips to the face. Inside: 2 white highlight bars (slanted, different widths), half-tone dots in the corners only, texture tiles, sunbursts. **Highlight bars cross the whole face:** each bar starts and ends outside the face, so only the face's own edge cuts it; never put the bars in a shorter inner clip frame (that makes a hard cut part-way down the card: G2 owner review). A deliberately short glint fades out with a gradient, it never stops in a hard line. Keep the centre clear for the icon and label. Inside components prefer an `fx` frame with the same radius and Clip content (it follows constraints; a group mask does not) | TC@12:48-14:51, TS@20:39 | cartoon, stud, anime |
| F-08 | **Blend modes** | Appearance → blend drop-down; hover to preview. **Soft light** = softer, **Overlay** = stronger (TC@14:24, TC@22:07). Lower the layer opacity if still harsh. Roblox UI has **no** blend modes: the result must be baked or rebuilt as Normal white/black at low opacity (handoff §1) | Soft light for cards/headers, Overlay for buttons and studs | all (bake) |
| F-09 | **Textures** | Image fill → Tile, scale the tile (stud, TS@9:50); a half-tone image in corners, flipped H/V for the opposite corner (TC@22:48); a sunburst behind an icon at Overlay (TS@44:36). Sunbursts, glows, sparkles, rings and shines come from the shared VFX library first (`references/effect-assets.md`). Textures never sit behind small text | TS stud = 4×4 studs per tile | stud, cartoon, anime |
| F-10 | **Outlined 3D text** | Fill (usually white); stroke **Outside**, join **Round** (no spikes on bold glyphs, TS@52:49); depth by either a duplicate below, moved down and set black (TC@24:48), or a drop shadow blur 0, opacity 100 %, Y ≈ stroke weight (TS@13:29). Figma's new drop shadow defaults to Y 4, blur 4, 25 %: set every value on purpose (Y 0 for glows and inner shadows, TC@6:05; Y ≈ stroke for text depth) | size 64 → stroke 4, Y 4; 46 → 3/3; 25 → 3/3; small → 2/2 (TS) | all except pixel (pixel: 2 px stroke, no depth) |
| F-11 | **Token ladders, not one-offs** | One outer outline weight per game. Radius, lip depth, inner stroke and text stroke each come from a small size ladder (S / M / L), and every control of a size uses the same step. Phone check (ui-design screen-contract §5): lines meant to read as thick ≥ 5 canvas px, lips ≥ 8 px, essential text ≥ 38 px. The Scale tool (K) multiplies stroke weights, so reset them after scaling (5 became 7, TS@41:46) | radius 10 (TC "like always"); outline 5 (TS) | all |
| F-12 | **Wells and panels** | Panel: black at reduced opacity + stroke (TS@3:05) or white face with dashed inner stroke + white halo (TC@4:42). Input well: rectangle with **inner shadow** X 0 Y 0, opacity 30 % (TC@5:45). Translucent dark panels 50-60 % (TP) | stroke 5 (TS); inner shadow 30 % (TC) | all |
| F-13 | **Padding and spacing check** | Select a layer, hold **Alt**, hover the neighbour: red numbers show gaps; nudge with Alt + arrows; grow a container 1 px if one side is off (TC@8:09). Multi-select cards and hover between them to read the gap (TC@18:02). After duplicating rows, select all and Align → vertical centre to remove 1 px drift (TC@40:29). Better: auto layout padding and gap so it stays exact | 9/9 text inset (TC@8:28); 30/30/30 card margins (TS@31:56), gap 24 (TS@30:29) | all |
| F-14 | **Recolour fast** | Select a group → Selection colours lists every paint; edit to swap gold → purple (TC@35:51). Copy a fill or stroke: click an empty spot in its row, Ctrl+C, select target, Ctrl+V (weight does not copy, TC@39:25). Best: colour variables per role and rarity for **solid** paints; gradient faces cannot bind variables in the Plugin API, so make rarity a variant property (or rewrite stops from the token table by script) | rarity gold / purple / green (TC) | all |
| F-15 | **States as variants** | Component set with `State=Idle, Focus, Pressed, Pending, Disabled, Selected` (+ `Cooldown` for timed actions; `Equipped`, `Locked`, `New` for items). Four marks that must never look the same (PROPOSAL, from TA@24:54 + ui-design D-04): **focus / hover** = a white ring that moves with the pointer or gamepad (TA's white outline); **selected** = persistent accent (brighter face + accent-colour ring); **equipped / owned** = a badge (check); **pressed** = the art moves (face drops by the lip depth) while the button's hit area keeps its size and place (motion record 10). The focus ring is white on dark or coloured surfaces and dark (e.g. navy) on white panels, so it always shows. Disabled: grey face and outline, no shadow, but the label and its reason stay at full opacity (contrast). Every variant of one state uses the same marks (all Pending variants show the spinner). Hover never carries meaning that touch and gamepad cannot get | — | all |
| F-16 | **Icons** | An icon must have a meaning written first (ui-design D-11). Icons may break out of their card for energy (TA@22:04), put them under the label so text stays on top (TS@47:50). Bitmap icons cannot take a stroke in Figma: vectorize (Vectorize Bitmap plugin, manual only, TS@15:35), use an SVG, or bake the outline in a raster editor (TS@17:39). Hard shadow on icons: Y 3, blur 0, 100 % (TS@17:17) | icon stroke 3 Outside (TS) | all |
| F-17 | **Mirrored ornaments** | Draw one corner, make it a component, place 4 instances flipped H / V (Shift+H, Shift+V; API: `relativeTransform = [[-1,0,w],[0,1,0]]` for H). One edit updates all corners and removes seams (TP@19:30-21:56) | corners only (TP@18:14) | pixel, anime, cartoon headers |
| F-18 | **Edge fades** | A bar that dissolves at its ends: linear gradient fill with opacity stops 0 → 100 → 0 % (replaces Photoshop motion blur, TP@15:42). Maps to a native UIGradient Transparency | — | pixel, anime |
| F-19 | **Clickable looks bright** | Bright, glowing, high-saturation surfaces read as pressable; dark, high-contrast fields read as drama or passive (TA@19:23). Use glow for the primary action only; one brightest element per screen region (measured: `ui-design/references/review.md` §6 S-17) | — | all (cartoon, anime most) |
| F-20 | **Overlap for depth** | A header or badge may overlap the panel below it; order layers so it sits on top and note the ZIndex for the builder (TA@8:01) | — | anime, cartoon |
| F-21 | **Check at play size** | Resample the screenshot to the phone fit (`look_check.py thumb --size 565x318` at f 0.294; screen-contract §5) and look again; detail that vanishes is noise, text that blurs is too small (TP@9:37) | — | all |
| F-22 | **Stress content** | Type the biggest number (9 digits, TS@51:43), the longest name, a long translation; fewer grid columns give bigger boxes for long names (TA@28:18). Headers, tabs and pills hug their text with padding (auto layout), never a fixed width | — | all |
| F-24 | **No-go overlay** | On every screen frame, a guide layer `no-go` (hidden in exports) marks Roblox's top-bar button rows (top-left and top-right) and the default thumbstick (bottom-left) and jump (bottom-right) zones in red at 20 %. Sizes are PROPOSAL (no fixed inset contract exists, RA-50); confirm them in Studio's Device Simulator for the smallest supported phone and update the overlay. Interactive parts never sit in it (ui-design D-07; measured from node bounds: `ui-design/references/review.md` §6 S-49). With the J002-D8 fit the canvas already sits inside `CoreUISafeInsets`, so the top-bar rows fall outside the canvas: mark only the thumbstick and jump zones, plus the top-bar rows if the screen uses the full screen. Full-screen menus over the thumbstick / jump zones: say in the spec whether touch controls are hidden while the screen is open (PROPOSAL, verify in Studio) | — | all |
| F-23 | **Save versions** | Figma autosaves, but name a version at each gate (File → Save to version history). The anime tutor lost his file to a crash (TA@25:46) | — | all |
| F-25 | **Grey frame first** | Build the picked wireframe in greys (white, three greys, black) with real text before any token: it proves the read order in value (`ui-design` SKILL §3 step 6). Keep it on `Wireframes`; the styled screen's luminance image must rank the same controls first (S-16) | — | all |
| F-26 | **Crisp where it matters, soft where it glows** | Key edges (button silhouettes, card frames, text strokes, focus rings) are hard and clean; soft falloff only for glows and shadows; no semi-transparent overlay or airbrush gradient across a face in clean styles. A screen that is soft everywhere reads mushy at phone fit, one that is hard everywhere reads stiff | — | all |
| F-27 | **One motif, at several scales** | Ornaments come from the game's own motif (a shape from its icons, logo or story object), built from a few basic shapes, abstracted, never a pasted symbol; place it at large (header silhouette), medium (card corner) and small (bullet, divider) scale; never on the decision path; a removable layer (S-27) | — | all |
| F-28 | **Overlaps keep an edge** | A badge, icon or label over a face of the same hue gets a value step or a stroke (S-22); a rarity badge on a rarity-coloured card is the usual case | — | all |
| F-29 | **Size steps** | Sibling elements of different priority differ clearly in size (big, medium, small); same-priority siblings are exact copies (instances of one component) | — | all |

## 5. Rules (final check, short)
- Every effect is marked native / baked / tiled before export; nothing relies on a blend mode, inner shadow, blur or dashed stroke at runtime.
- No text, number, price or name inside baked art. Fonts exist in both Figma and Roblox (handoff §2).
- One outline weight per game; radius, lip, inner stroke and text stroke from one size ladder each.
- Controls are components with state variants; nothing ships as a one-off duplicate.
- Generated images: made with ChatGPT first, originals only, logged, no text in them (`references/image-generation.md`).
- In the owner's Figma: write only in the file the brief names or a new file you created; return node ids.
- No styling before the grey frame is approved; styling never moves the grey frame's layout.

## 6. Self-check before returning (inputs and commands: `ui-design/references/review.md` §6)
- [ ] `Flow` and `Wireframes` pages hold the flow with tap counts, the options contact sheet and the grey frame (S-03, S-08, S-10); the phone layout frame's tap targets pass the hit-target check from their node bounds (S-49).
- [ ] Every control is a component with its state variants; instances only on screens; every variant of a state uses the same marks.
- [ ] Alt-check padding passes; auto layout gaps exact; no 1 px drift; nothing touches or overlaps by accident; no layer shows through a popup.
- [ ] Styled screenshot: read order equals the grey frame (S-16), extremes and glow on the focal control only (S-17), contrast (S-18), colour roles (S-19), gradients (S-21), overlaps (S-22), phone fit (S-23), side by side with the target image (S-25); numbers for every state, images for failures and key screens.
- [ ] Effect textures picked from the VFX library (catalog code + id recorded) or the spec says why not.
- [ ] Layer table marks N / B / T / L for every layer; baked parts exported at the right size; 9-slice insets given.
- [ ] Figma link and node ids in the hand-back; every check labelled MCP-verified (Figma) or not verified.
