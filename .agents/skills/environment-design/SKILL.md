# Environment design: a place the player can read, feel and play

## 1. When this skill starts
A stage, level, hub, lobby or world is planned, built, changed or reviewed. It answers: what must the player notice and feel in each area; how the place guides without words; what is built where; how light, air, sound and motion tell the player where they are; what proves it works before the owner sees it.
**The rule above all others:** the place is the backdrop of the game. The route, the objective, hazards, characters, pickups and effects read before any decoration, on a phone, in the busiest moment. A beautiful place that weakens that read has failed; mood comes second, and both come from the same few decisions (shape, value, light, colour, sound).
**Who owns what** (CO04 O): game designer = routes, interactions, pacing, cover, sight lines, blocking surfaces (`level-design`); art director = style limits, value bands, reserved colours (art bible); modeler = every reusable asset; sound designer = how it sounds; VFX designer = how effects are built; the environment designer = the place: space, terrain, assembly, set dressing, lighting, atmosphere, ambience map, placement, transitions, and what must stay visible. The owner decides.
**Order:** this skill §3 → `environment-craft` for each build step → this skill's review (`references/review.md`) → owner.
**After a compaction:** re-read §3, §5, §6 and §7 of this file and `references/review.md` §7 before you continue.

## 3. Steps (each step's output is a file; owner gates in bold)
Image budget for every step (owner light-check rule): numbers for every case; images only for a failing number and for the key views of `references/review.md` §3; the full camera set once, for the release candidate.
1. **Intake.** From the game designer: the stage's job and conflict sentence, the route graph and route table in seconds, the blockout brief per node (stop or pass, sight lines to keep clear, key positions, floor types with the smallest gameplay object, events that must be heard: the node geometry of `level-design/references/review-artifact.md` §1), hazard sheets, the read rank, the material-to-rule table, orientation conventions, the approved blockout limits (collision, cover, sight lines). From the art director: the art bible version and its craft-standard rows I build against (value bands per layer in both units and the saturation band for environment materials, separation targets, reserved colours with their shape partner and allowed share, key light per place, shape vocabulary, palette roles, stylisation level); a missing row stays a `PROPOSAL` starting value and a question to them. From the game profile: camera, player envelope, walk speed and jump (measured in Studio), target phones, players at once. Missing fact that changes a hard-to-undo choice: ask; otherwise state the assumption and keep the work easy to change (W02 O; ST01 O).
2. **Read plan** (`references/read-plan.md`) before any image: the place's personality in 3-5 words, 3 story facts, per key view the ranked reads and critical facts, the focal point per view, the smallest gameplay object, the stage's value band and reserved colours, theme cues, the ranked work list agreed with the game designer (play spaces and routes, then landmarks and first view, then filler), stop criteria and a pass budget.
3. **Research, set list, options.** Real-world reference for the place's specific details, then the game's own anchors; a keyword table; the set list (what players expect to find, iconic before trivia; plan every decoration, FS-P06, FS-P09). One option round: 3 distinct directions at equal low finish, one deliberately unexpected, the first batch labelled warm-up; recommend one with the reason tied to the read plan and record why each other one lost (`read-plan.md` §3). Key-place reference images with `reference-images` (concept and environment families; real photos first for real places, FS-R01), each annotated as a spatial target (PR-02). **Owner reviews the references** (FS-R06).
4. **Site plan, then blueprint** (`stage-blueprint.md`, the read plan attached as its §L): zones, path network, heights, terrain per area, scale sheet, elevations against the reference silhouettes, guidance per decision point, the first view from spawn, each boundary dressed as the world (2-3 fictional answers per constraint, picked with the art director), built-where table. Check the plan with a script, not by eye (FS-P07). **Owner approves the blueprint before any building** (FS-P01, FS-P05).
5. **Greybox, then the grey value pass** (how, in order: `environment-craft` §3 steps 2-4). One asset round trip Blender → Studio first (ST03 O); the greybox in Studio at true scale with a player dummy and a known-size object in every space; walk it at walk speed with the real camera (BW02 O; W03 O). Still in grey: the key light direction is chosen by the numbers (`references/light-and-air.md` LA-15), the first view and each decision view captured, dead space marked on a top-down. Change the layout here, where it is cheap. (G2 for an L job: the playable greybox.)
6. **Target slice.** The hardest representative section to final quality first, with player dummies in typical avatar colours, the smallest gameplay object, typical effects and UI in view, at the lowest and the highest graphics setting (W04 O). The art director reviews; the owner rules on direction changes.
7. **Full build in passes over the whole stage**, a capture review after each (`environment-craft`): art blockout snapped to the greybox → terrain and kit → set dressing (story clusters, clean floors, grounding) → the mechanics' visuals → light, atmosphere and post effects, dated after the last route change → ambience map in place. Breadth first, then polish (FS-H05); no area more finished than its equals.
8. **Self-review** (`references/review.md` §7, every line with its named input): fix and re-shoot before anyone sees it; then the review packet with the 3 weakest points and a could-not-check list.
9. **Hand-offs and owner.** Briefs to the sound designer and VFX designer (from the ambience map), the modeler (new assets; in-set capture returned for each piece), the game designer (route proposals), the art director (look review), the studio operator (play-tests, busiest-moment and device captures); `rules/messages.md` format (`environment-craft/references/handoffs.md`). **Owner sees the packet (G3).**

## 4. Craft core (what separates a great place from a pile of nice objects)
Detail and checks for each row live in the reference named in it; review lines in `references/review.md` §7.
| ID | Practice | Evidence |
| --- | --- | --- |
| E-01 | **A place is a playable composition.** Shapes, light, sound and motion tell the player where they are, what matters and what can happen next. Prove it in the real Roblox scene at the game camera on a phone-size view, never with one polished render. | EC1 O; J018 |
| E-02 | **The route is the game designer's.** Keep every approved edge, opening, cover piece, sight line and timing; art snaps to the approved greybox; propose layout changes in the open (`place-reading.md` §1). | RU01 O; PR-01; J018 |
| E-03 | **Notice first, decorate second.** At each decision point decide what the player must spot and why it reads, then check it in the real camera. Far landmark orients; near cue gives the next move; the first view after spawn frames the goal (`place-reading.md` §2). | RU02 O; PR-04, PR-05; J018 |
| E-04 | **Real scale, measured against a player.** Real-size buildings felt like miniatures; the owner wants rooms and furniture that make sense at player size. 1 stud = 28 cm is only a unit conversion, not a size target. A player dummy and a known-size object stand in every greybox and review scene. How much a game exaggerates is the owner's decision. Three clearances (visual, collision, camera). | FS-S01 ("it's almost like you're making a miniature on purpose", D-091); PR-11-PR-16; J018 |
| E-05 | **Terrain everywhere.** Every area has ground with height changes and visible layers that fit the theme; never buildings on a flat plane. Play floors stay walkable and clear; every height change in a play space is on the game designer's list. Paths join a network; every door meets a path; the main walkway is never cut by scenery; every pit, river and high place has a way out. | FS-T01 ("we want a little bit of terrain in every stage", D-106); FS-T03-T05; J018 |
| E-06 | **Finished on every face.** Players walk round everything: back and side walls get windows or equal detail; walls close on all sides; every enterable room is furnished and dressed; directional pieces face the right way; organic shapes stay organic; stepped or layered covers have the vertical faces between their levels, checked from a low oblique view. | FS-B01 (D-192), FS-B02, FS-B03, FS-B06, FS-B07 |
| E-07 | **Compose for the approach.** The main face of a landmark points at the route; the landmark is the tallest, clearest shape with a unique silhouette; each structure has 2-3 iconic traits that must read at play distance; shape flow (paths, roof lines, light) points at the focal point. | FS-S08 (D-108); FS-S09; J018 |
| E-08 | **Light and air serve readability first, mood second.** One key light direction per place, chosen in grey; the lightest, highest-contrast area is the objective; haze lowers distant contrast but never hides information; the route reads at the lowest quality without shadows or optional effects. Engine lighting, per stage, with its own sky when needed (`light-and-air.md`). | FS-L01 (D-126), FS-L03 (D-139); J018 |
| E-09 | **Every sound and motion has a cause.** Each zone gets its own plan, borders blend, streaming is planned, gameplay cues come first; nothing fast or bright moves near a sight line (`ambience.md`). | AB-01-AB-12; J018 |
| E-10 | **Someone lives here; time has passed.** Three story facts per stage (who, what happened, climate and age), each shown by visible props, wear and layout at backdrop contrast; calm space where the player must read, detail where the player stops (`place-reading.md` §4). | PR-17-PR-22; J018 |
| E-11 | **A biome is palette, material, wind and sound together,** with a narrow vocabulary and 2-3 theme cues so the place is never generic. Stages feel different as a whole, and each new world takes players somewhere clearly new; repeating a kind of element across stages is fine. | PR-24; FS-P10 (D-194); J018 |
| E-12 | **Reuse a kit; no visible duplicates.** A shared prop kit first, a few approved building types with variants, unique shells sharing one trim sheet where a layout is bespoke; no piece seen twice at the same angle in one view; ask the modeler for new pieces in the brief format. | FS-B11 (D-098); PR-20; J018 |
| E-13 | **Build and test the heaviest piece first,** then decide; do not pay detail for parts nobody uses. | FS-V11; FS-T09 (D-121) |
| E-14 | **Budgets are measured, never invented.** Platform caps are not targets; the phone trace of the busiest scene sets the budget; the owner sets the frame-time target. | `review.md` §5; BT01-BT09 |
| E-15 | **The environment is the backdrop layer.** UI and gameplay effects own the value extremes, characters come next, the environment keeps the narrowest value and saturation band and never reaches pure black (`light-and-air.md` §4). | J018 |
| E-16 | **Reserved colours and fast motion stay out of decoration.** Danger, team, route and interactable hues belong to gameplay only; the player band (floor to head height) stays neutral; strong colour goes above head height; a hazard that must glow is tamed until characters still separate in front of it (`light-and-air.md` §4). | J018 |
| E-17 | **Floors stay clean for the smallest gameplay object.** Ground cover is added, then cut back to a whisper in play areas; detail clusters sit above head height, at edges and at stop points (`place-reading.md` PR-19, PR-44). | J018 |
| E-18 | **Every piece says what it is and what you can do.** A climbable ledge looks like every other climbable ledge; materials follow the gameplay rule; each floor material has its footstep sound; hazards show their source and containment (`place-reading.md` PR-34, PR-41; `ambience.md` AB-15). | J018 |
| E-19 | **Ground every object.** A base or skirt, no straight clean seam where mesh meets ground, a thin contact shadow, a hint of the object's colour on the ground near it (`place-reading.md` PR-45). | J018 |
| E-20 | **Controlled variation, never noise.** No flat single-colour fills on large surfaces; sibling shapes in clear size steps (big, medium, small); variation stays inside the colour family and the value band and never touches what carries meaning (a marker, a hazard edge, a route cue) (`place-reading.md` PR-20, PR-46; `light-and-air.md` §4). | J018 |

## 5. Rules (final check, short)
- The owner approves the blueprint before building and sees only reviewed work. Agents never mark work owner-approved (FS-P08).
- Route, interaction, cover, sight line and pacing changes are proposals to the game designer; art never moves collision, cover or approved openings. Craft choices of sound, VFX, models and rigs stay with their owners (DN08 O).
- No number without a source: owner D-id, layout, measurement, doc file:line, or `PROPOSAL`; unknowns stay `UNKNOWN` (DN02 O). Tutorial values and starting values are examples, not presets.
- The environment stays inside its value band, never pure black; reserved gameplay colours and fast motion stay out of decoration.
- Gameplay-critical information never depends on sound alone, on colour alone, on shadows or on optional effects; it reads at the lowest graphics setting.
- Never copy another game's layout, landmarks, names or assets; real places and cultures checked for accuracy and respect (PR-31). Dressing that shows blood, violence, alcohol, adult venues, or real brands, logos or franchise designs goes through `platform-policy` before it lands (content maturity, IP).
- A passing automatic check (outline score, validator, audit, tool number) never overrules a capture that shows a defect (FS-V05); a tool number without a tolerance is MEASURED, never PASS.
- When a budget forces cuts, ask the owner what to protect (FS-P11); cut by measured cost, never by instance count.
- Never claim you saw, heard, played or measured something without evidence from this task. Label every check gate-verified / MCP-verified / owner-confirmed / not verified.

## 6. Self-check before returning
- [ ] Intake done; assumptions stated; read plan written before the first image; option round recorded (pick, reasons, rejections); references reviewed by the owner; blueprint approved (date and owner's words).
- [ ] Greybox walked at walk speed; key light direction chosen in grey; dead space marked and resolved.
- [ ] `references/review.md` §7 run (a fix job: its fix-job lines): every line has a result, its input and a label; failing lines fixed and re-measured, or listed with the reason.
- [ ] Ambience map complete for every zone and source; borders and streaming tested; listening review done or "pending".
- [ ] Review packet: key views at the lowest and highest graphics setting, scene audit clean (0 floating, 0 buried), budget numbers with sources, passes and images used against the budget, 3 weakest points, could-not-check list.
- [ ] Hand-off briefs written in the `rules/messages.md` format.

## 7. Core principles for this craft
Each universal principle as it lands in my work, with an example from a Roblox stage and the check I run (input in brackets; review line ids from `references/review.md` §7).
| # | Principle in my work | Example | Check |
| --- | --- | --- | --- |
| P1 | The gameplay read comes first; the place is the backdrop. Routes, objectives, hazards and characters read before decoration. | A mossy ruin is gorgeous but the coin pickups vanish on its green floor: the moss goes, not the coins. | Busiest-moment capture at phone size: every critical fact found; light and dark characters reach the character separation target against their ring (RD3, VB2) [studio-operator capture + numbers] |
| P2 | Judge where players meet it: the game camera, phone size, the real place, moving, busy, lowest and highest graphics. | The editor shot of a lantern street looks rich; at the lowest setting with shadows gone the alley to the shop disappears. | Key views at both quality settings and at the smallest phone viewport (QV1, QV2) [captures + numbers] |
| P3 | Decide what is read first; spend contrast only there. Lower the surroundings before raising the goal. | The forge glows; the walls around it are darkened a step instead of brightening the forge. | `look_check.py value` with the focal box and its own-contrast run: wins the focus by the RD2 rule (VB3) [numbers] |
| P4 | Big before small: layout and routes, then composition and kit, then dressing, light last. | Light polish waits until the last route change; the sun direction is picked in grey on the greybox. | Job record: greybox played, grey pass dated before dressing, light pass dated after the last route change (PS2) [record] |
| P5 | Shape carries meaning: the landmark is the tallest, clearest shape; directional shapes point at the goal; collision stays simple. | The volcano's peak is the tallest shape from every spawn; its lava runs point down toward the exit. | Landmark height above its neighbours from part sizes; shape flow traced on the grey first view (RD2, RD13) [numbers + 1 capture] |
| P6 | Less is more: few elements, rest areas, indicate masses. | Grass cards only at path edges; the plaza stays a quiet floor so trap markers read. | Smallest-object floor check; detail clusters on the read plan's spots (FL1, FL2) [numbers + thumb sheet] |
| P7 | One code for meaning: reserved hues out of decoration, one look per gameplay read, one material per gameplay rule, one orientation convention. | Red means danger in this game, so the market awnings are ochre and teal. | Reserved-hue pixel share in the environment boxes, gameplay objects excluded, near zero; material table vs place (VB4 by M3, RD6, FL9) [numbers] |
| P8 | Timing tells cause and effect, in my part: rest and action alternate along the route; a reveal follows the turn that hides it; a look change is hidden behind a fade or a doorway. Applies in part: routes and pacing are the game designer's. | The canyon walk opens on the boss arena only after the last bend; the sky swap happens during the gate fade. | Route table: a view or something to do within each segment's limit; reveal positions match the plan (RD10) [route table + captures at reveals] |
| P9 | Push what must read past real, on a believable base: landmarks taller, doorways sized for the camera, markers bigger than real signs. | A 10-stud doorway for a third-person camera; the shrine is twice real size but its steps keep walkable height. | Exaggerated relations listed in the scale sheet; step heights measured against the jump (FL7) [numbers] |
| P10 | The place has a character: personality words and story facts drive every shape, material and prop. | "Rigid, old, timeless": square stone, deep chips, sand drifted against the north walls. | Every main area shows one assigned story fact; the art director names a story fact at the check-in (FL5) [captures + partner] |
| P11 | One world, one style: the art bible's shapes, palette and stylisation level, matched to the characters. | The new swamp uses the game's knife-like rock vocabulary, not soft blobs. | Stage capture beside 2-3 approved anchors (FL8); every zoo material's lit face within the palette distance of a bible palette role as rendered under the same light (VB11 by M12) [numbers + 1 capture pair] |
| P12 | Controlled variation and life, never exact repetition, never noise. | Fence posts rotated and leaning by one reason (wind from the sea), never at random. | No piece twice at the same angle in a key view or along a repeated facade's camera path; every large surface's `hue_spread` above its flat limit on its lit side, a value texture in one hue failing as monochrome (FL3, VB12) [captures + numbers] |
| P13 | Problem, constraints and target first: the read plan comes before any image. | Intake lists the route table, hazard sheet and value band before the first reference prompt. | Read plan exists and is dated before the first image (RD1) [file] |
| P14 | Research, many distinct options, a reasoned pick. | Three cave entrances: a collapsed mine, a root-bound hollow, a carved temple door; one picked for the "abandoned" fact. | Option sheet: 3 distinct directions, one unexpected, pick with reason, rejections recorded (PS1) [file] |
| P15 | Cheap stages first; gates freeze decisions; not precious. | A layout that fails the greybox walk is reshaped there, not dressed around. | After the blueprint gate nothing approved moved without a decision; collision diff vs greybox (RD9, PS2) [numbers + record] |
| P16 | Critique against the goal, one named problem at a time, by layer. | "Players miss the cave" is traced to the cue being off-camera on approach before anything is added. | Each fix names the problem, its layer and the before/after capture from the same camera (PS4) [record + captures] |
| P17 | Build for the next craft and the engine: zones and anchors for sound and VFX, kit briefs for the modeler, budgets measured. | The waterfall's anchor sits at the impact pool so the sound designer's source has a visible cause. | Scene audit map vs place clean; downstream briefs have no open questions (AM2, QV3) [numbers] |
| P18 | Know when it is done: written stop criteria and a pass budget; new ideas past the gate become follow-ups. | Stop when every §7 line passes at both settings; a new plaza idea after G2 becomes a ticket. | Hand-back states stop criteria met and passes used (PS5) [record] |
| P19 | Feedback follows the real outcome, in my part: new views and reward spaces sit at real achievements and natural pauses; no celebration dressing at a place the player has not earned. Applies in part: feedback is mostly other crafts' work. | The vista over the next world opens at the top of the climb, not at the bottom. | Reveal and reward-view positions match the route's achievement points (RD10) [route table] |
| P20 | Every player can read it: hazards and routes read by shape and value with colour removed; fog never hides a hazard; every intense ambient channel (lightning flash, storm tint) can be reduced and stays under 3 flashes a second. | Lava reads by its dark crust rim and glow shape, not only by being red. | Grey view of each hazard: rim and shape read; with the final haze on, route cues and hazards still reach their separation target; storm spec names its off path and flash rate (VB13, VB7, AM3) [numbers + spec] |
