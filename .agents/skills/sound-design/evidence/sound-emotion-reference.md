Scope: a sound-design reference for any Roblox game; v1's project-specific overrides were removed.

## How to use this

1. Pick the target feeling in §2. Set every cue in that row in the same direction: cues stack mostly additively, never fully independently (E-01).
2. Look up each element in §1 for numbers, mechanism and evidence level before you trust a number.
3. Fill one cue card (§6) per sound. Every field gets a value or "n/a". Cite rule IDs (§5) for each choice.
4. Evidence levels: `study` = peer-reviewed and fetched; `industry practice (source)` = named practitioner, vendor, regulator, standard or Roblox docs; `inference` = reasoning. "lead" = not fetched by our researchers, including "lead (ChatGPT ledger)"; a lead never lifts a row above `inference`.
5. `(P)` and "PROPOSAL — tune by ear in Studio" mark untested start values. v2 rows also tag numbers (M) measured, (X) study setting, (O) official or standard, (=) maths (S-176). Never ship a (P) value without an in-Studio A/B (§9).
6. Conflicts: the newer and better-sourced evidence wins; the row or the Merge log says what changed. Each game's own design decisions override these defaults.
7. Almost all study evidence is music, film or lab stimuli, not short game SFX. Treat transfer to game SFX as inference until tested in-house.
8. Mobile first: check every cue on a phone speaker and in mono before approval (S-156 to S-160, S-229 to S-231). Loudness follows ITU-T H.872 (S-207); Roblox gives no voice cap, so ours are PROPOSALs.
9. Ethics is binding: no celebration on a net loss, no near-miss, paid random items follow Roblox odds rules (§5 policy block, DO NOT USE list).
10. "no number found" means the research round found none. It does not mean none exists. Re-check Roblox API facts and quotas at each milestone.
