# Launch timeline: <game> · target launch <date, timezone> · revision <n>

Workflow: `marketing-design` (launch), `marketing-craft` (kit). For a new game the marketing agent runs at **high** effort (owner J012-D1). Copy to `knowledge/jobs/<job>/marketing/launch-timeline.md`.

**Rule of use.** Four weeks before to four weeks after is the owner's planning window, not proof that a game needs it, that launch brings recommendation traffic, or that every channel must be used. A stage moves on only when its decision is made. A delayed game is never marketed with a false date. Nothing is published, posted, spent, sent to a creator or signed without an owner decision id.

## A. Release gate (owner approves each before any publication or spend)
| # | Gate item | Evidence | Decision id |
| --- | --- | --- | --- |
| G1 | Product, format, objective, audience and region reviewed; no blanket age assumption | | |
| G2 | Promise matches the build (proof sheet); rights register; disclosures | | |
| G3 | Creator deliverables, pay, rights, adult representative where a creator is a minor, who monitors | | |
| G4 | Spend: total loss ceiling, duration, currency, funding source; auto-reload off unless approved | | |
| G5 | Integrations: registration, moderation, runtime eligibility, fallback for ineligible players | | |
| G6 | Tracking ids, cohort maturity dates, net-receipts accounting; labels forecast / attributed / incremental | | |
| G7 | Pause owner and escalation route for spend anomalies, moderation failure, misleading content, player harm | | |

## B. Weeks
| Window | Dates | Marketing work | Owner and analyst decision | Status | Decision id |
| --- | --- | --- | --- | --- | --- |
| 4 weeks before | | hook statement, playable proof, audience hypothesis, rights inventory, source and policy check; trend scout signals with dates | approve the fantasy being sold; name what is still unproven | | |
| 3 weeks before | | title candidates (title checklist), separate icon and thumbnail concepts (image briefs), page draft, capture plan | pick coherent candidates; reject promises the build does not hold | | |
| 2 weeks before | | real gameplay captures, short-video drafts, creator shortlist and offer terms, community moderation plan; featuring submission if used (lead time from the live form) | decide whether any outside campaign fits; no spend by default | | |
| 1 week before | | approved launch kit, destinations checked, event and announcement drafts, measurement dictionary (with the analyst) | confirm tracking, attribution limits, support, release fallback | | |
| launch day | | publish only approved assets through the owner's accounts; record exact versions and times | compare arriving-player quality and technical health with the plan | | |
| week 1 after | | channel and cohort report, player-misunderstanding review, creative fixes | fix broken promises or onboarding before buying more impressions | | |
| week 2 after | | a creative test only where traffic supports one (analyst); creator and community review | separate content results from game retention; any budget change | | |
| week 3 after | | update kit tied to a real playable change; returning-player message | does the update give a real reason to return, without hype | | |
| week 4 after | | acquisition and retention assessment (mature cohorts only), rights and asset archive, next-cycle proposal | continue, revise or stop each channel | | |
