## Event Sequencer

Source: M `resources/modules/event-sequencer.md` (mirror of the official page), plus live extract of https://create.roblox.com/docs/resources/modules/event-sequencer read 2026-10-21. Description from the docs only; I did not install or run the module.

| Topic | What the docs say |
| --- | --- |
| What it is | "EventSequencer" is a Roblox developer module (a Creator Store package) for "live, cross-server events and cutscenes on a structured sequence of actions and triggers" (`:11`). You place the `EventSequencer` model in `ServerScriptService` and it runs on play (`:47`). It builds on scheduled configurations of audio, animation and tweens; moves between scenes across servers; supports seeking for testing (`:13-15`). Roblox says it was used in the Twenty One Pilots and 24kGoldn concerts (`:17`, a vendor claim). A Concert template shows it (`:23`). |
| Is it current | Probably yes. Evidence: the official page is live with no deprecation, legacy or unmaintained notice (live extract, 2026-10-21); the mirror manifest lists the page as not dropped (`manifest.json:3145-3148`); GitHub history of the page shows a doc commit on 2026-07-07 (extract of github.com/Roblox/creator-docs/commits, a bot sync of internal docs, so it shows the page is still carried, not that the module changed). The page itself is undated and gives no module version. I did not inspect the Creator Store asset, so its last update is unknown. |
| Structure | Two modes: replace mode (default; a scene's `Environment` folder replaces Workspace, Terrain and Lighting content, `:53`) and inline mode (keeps existing objects; set the `Inline` BoolValue; "best for existing games", `:59-75`). A scene is a folder with a `TimeLength` attribute (seconds), an `Environment` folder (`Client`, `PlayerSpawns`, `Server`, `Terrain`, `Lighting`), an `Events` folder, and `Client` and `Server` schema scripts (`:79-159`). Scenes must sit in `ReplicatedStorage` for the event flow (`:92`). Hooks: `OnSetup`, `OnRun`, `OnEndScene` (`:167-177`). Do not call `wait` in `OnSetup` or `OnRun` (`:350`, `:406`). |
| Configurations (the whole set) | `audio` (creates a `Sound`; `StartTime`, `SoundId`, `Volume` default 0.5, `:447-480`), `animate` (rig, `AnimationId`, `Speed`, fades default 0.2 s, `SyncToAudio`, `:503-560`), `tween` (`StartTimes`, `Object`, `Info`, `Properties`, `:591-628`), `interval` (`:665-706`), `schedule` (`StartTimes`, `Skippable`, `:731-760`), `inform` (register connections and modules for cleanup on seek, `:780-856`). |
| Scenes and cross-server | `loadScene(sceneName, startTime?)` with a 5 second grace period; `seek(time)`; `setSceneWarningTime`; `onOrchestrationFinished`, `onSceneLoadedForClient` and two ending-warning events (`:858-1151`). The page says it synchronizes visuals "across multiple servers" (`:14`) but gives no mechanism and no accuracy figure. |
| Sync inside a scene | `SyncToAudio` ties an animation, tween, interval or schedule to a position in a configured `audio` sound (`:556-557`, `:624-625`, `:702-703`, `:756-757`). Audio is a `Sound` object, not the `AudioPlayer` and mixer-clock scheduling of FC-32. |
| Late join and seek | `tween` is "preserved in seeking and in dynamic join" (`:593`). `schedule` has `Skippable` (default `false`): when false, every start time before the join or seek moment fires at that moment; when true only later ones fire (`:753`). `inform` exists so seeking cleans up (`:782`). Seeking is permission-gated by place id, user ids and group ranks through `setSeekingPermissions`; "users simply enjoying the event should not have the ability to control its time flow" (`:193`). |
| Camera | Not mentioned. A search of the page for "camera" finds nothing. A camera move could only be built by hand inside a `tween` (any object and properties) or a callback; the page does not show it (my inference), and says nothing about taking or returning camera ownership. |
| Not covered by the docs | Camera takeover and restore; letterbox bars; subtitles; a skip control for ordinary players (the only seek is permission-gated and for staff); private per-player story scenes (the model is one shared event timeline); streaming prefetch or readiness; input lock; death, respawn or disconnect exits; server-side reward authority; `AudioPlayer` scheduled playback; animation markers. "Not covered" means the page is silent, not that it cannot be done. |
| Use it or build a player | My inference from the above, not a Roblox statement: use Event Sequencer for shared, multi-scene live events (concerts, countdown shows) where everyone sees one server-driven timeline, late joiners should land mid-show, and staff need to seek. Build the studio's own player for a private, camera-driven, skippable story cutscene, because the page gives no camera, subtitle, skip or exit handling. Replace mode rewrites Workspace, Terrain and Lighting, so in an existing game use inline mode or neither. |

## Corrections the skill must carry

Corrected claims: none. Dropped claims: none outright. The items below are what the skill must say or avoid so that a true claim does not mislead. One line each.

1. FC-46: drop the Moon Animator version `V36000` and listing date 2026-08-19; they are unverified. Keep only "third-party plugin" (documented).
2. FC-23 / FP:697: the property is `FieldOfViewMode`, never `FOVMode`. Say `FieldOfView` is a vertical angle (1 to 120, default 70) and set the mode to `Vertical` explicitly.
3. FC-24: never write "FOV is horizontal"; the camera overview wording ("in the direction defined by `FieldOfViewMode`") is looser than the API wording.
4. FC-40: `Player.FrustumStreaming` is the enum `FrustumStreamingMode` (`Default`, `Enabled`, `Disabled`, `Automatic`), set on the server only; "restore the prior mode" means store the previous enum value; `Default` currently acts as `Disabled`.
5. FC-39: `AddReplicationFocus` and `RemoveReplicationFocus` take a `BasePart` (server only); keep the part to release it. `RequestStreamAroundAsync(position: Vector3, timeOut)` yields, is temporary, gives no guarantee, and with no timeout waits effectively forever.
6. FC-41: `PreloadAsync` does nothing for `SurfaceAppearance` and `MaterialVariant`; a finished preload does not prove those textures arrived.
7. FC-32: scheduled audio returns an `int64?` action id for `AudioPlayer:Cancel(actionId)`; `Play` and `Stop` are documented to replicate server to client, but `atTime` is a per-machine mixer time, so schedule from the client. Cross-client accuracy is not documented.
8. FC-29 / FC-30: Animation Graphs are live since the 2026-07-15 announcement; State Machine and Expression nodes were announced as Studio beta on 2026-10-08 and, per the thread's FAQ, work only in Studio. The docs pages themselves are silent on both; cite the DevForum posts with their dates and re-check before use.
9. FC-21: "`Camera.Focus` does not load distant sets" is an inference; the docs only say it prioritizes graphics work near the point and must be updated every frame while `Scriptable`.
10. FC-44: `ReducedMotionEnabled` is a player preference on `GuiService` described for UI motion; Roblox does not apply it to scripted cameras, so the cutscene must honor it itself.
11. FC-47: freecam is for the experience owner and editors (and Studio playtests), not a player feature.
12. N3-FC-01 / N3-FC-02: "a finished cutscene must not grant a reward" and "test every exit" are studio rules built on documented facts; do not present them as Roblox sentences.
13. FC-20 hazard: setting `Workspace.CurrentCamera` to a new `Camera` destroys other cameras parented directly to Workspace, and camera-parented post-effects die with their camera; keep spare cameras in a Folder or Model.
14. FC-43 / FC-44: the mirror and the live extract disagree on whether `PreferredTextSize` and `ReducedMotionEnabled` are ReadOnly; read them, never write them.
