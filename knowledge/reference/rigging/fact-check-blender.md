Both papers pin 5.2. I found no 5.1 to 5.2 change that breaks a fact below, but the pin and the install differ (see RB22).
- Verdicts: confirmed (source matches), corrected (source gives a different value or procedure), partly (matches with a limit or a missing piece), unverified (not found), contradicted (source says the opposite). "Extra" in the note column = a finding the papers did not claim.
- Source IDs in column 4 are the papers' own (B0-B10, D01-D36). C and CL numbers in notes point to the claims tables of notes 01 and 02.

## Settled issues (a) to (e)

| issue | answer | rows |
| --- | --- | --- |
| (a) B7 cited for Actions and slots | B7 is the 5.2 Animation and Rigging release notes. Its key line is real, but the page has nothing on Actions, slots or channelbags. The true sources: slotted Actions arrived in **4.4** (RN 4.4 animation_rigging), the legacy Action API (`action.fcurves`, `action.groups`, `action.id_root`) was removed in **5.0** (RN 5.0 python_api), the 5.2 manual page `animation/actions.rst`, and the API pages `ActionSlot`, `ActionChannelbag` and `bpy_extras.anim_utils`. | RB15, RB16, RB30 |
| (b) "constraints are not saved in FBX" and the current exporter | Applies. The sentence sits in the Compatibility section of the page titled "FBX (Legacy)", but that page also documents the add-on exporter (anchor `bpy.ops.export_scene.fbx`). "Legacy" in the title refers to the old Python importer. The new FBX page says to use the add-on for export. There is no second exporter in 5.2.2, 5.3 or `main`. The exporter source samples evaluated frames and writes no constraint or driver data. | RB12, RB13 |
| (c) FBX `global_scale` default | **1.0**. Source `scripts/addons_core/io_scene_fbx/__init__.py` (5.2.2) and BUN (5.1) agree. The manual text "10 is the default" is stale. Also `apply_scale_options` defaults to `FBX_SCALE_NONE` ("All Local"), not the "FBX Units Scale" that Roblox asks for. | RB31, RB23 |
| (d) vertex shape keys via FBX in 5.x | **They export**, as FBX BlendShape deformers, when the mesh has more than one key block. The manual line "vertex shape keys are not written" is stale. With Apply Modifiers on, any enabled non-Armature modifier forces an evaluated copy and the shape keys are lost. 5.1 added shape-key normals. Whether Roblox accepts them is a Roblox question, not checked here. | RB32 |
| (e) Preserve Volume wording | Manual and RNA say "quaternions". The 5.2.2 code path is **dual quaternion skinning**. The Python property is `ArmatureModifier.use_deform_preserve_volume`. For a Roblox preview keep it off (RP:281 is right). | RB09 |
