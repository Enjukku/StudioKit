# Riot craft library (J018)

## 1. What this is and how makers use it

One library of the craft knowledge in the 14 Riot videos the owner supplied (17 reader extracts, 649 extract findings), merged into 427 library findings across 21 topic files, plus 18 universal principles. Stage 1c (the DestructionSimulator cross-check, `knowledge/jobs/J018-riot-craft/ds-cross-check.md`) added 16 findings and 2 principles and 32 extra lines marked "(DS)" in existing findings: the library now holds 443 findings plus 20 universal principles. Every finding is written for our pipeline (AI makers; ChatGPT reference images; Blender by Python and MCP; Roblox Studio through the Studio MCP; sound as cue cards; checks through captures at the game camera, grayscale and black-fill views, thumbnail sizes and the kit tools) and is tagged with every role it helps.

| File | Use |
| --- | --- |
| `universal-principles.md` | **The master** (owner decision J018-D1, 2026-10-21). Not a skill. Every role's books get a "Core principles for this craft" section that states each applicable UP for that role's own work with its own examples and checks. Stage 3 reviewers check those sections against the master (no contradiction, nothing important missing). A later fix goes into the master first, then into each role's section. |
| `<topic>.md` (21 files) | The library findings by topic. Makers rebuilding a role's books read the findings tagged with their role (the lead's `matrix.md`, generated from the `roles` fields, lists them) and turn them into the book's own standards, steps and self-review checks, in the agent's own voice, without citations. |
| `matrix.md` | Finding x role matrix, generated by the lead from the `roles` fields (not written by hand). |
| `knowledge/jobs/J018-riot-craft/synth/merge-plan.md` | The coverage record: every extract finding ID mapped to its library finding(s). |

How a maker uses a finding: `principle` and `why` become the standard; `apply` becomes steps; `check` becomes a self-review line; `mistake` becomes a "do not"; `roblox_fit` keeps it true for Roblox. Strong, checkable findings beat long lists: prefer the finding's check over restating its principle.
