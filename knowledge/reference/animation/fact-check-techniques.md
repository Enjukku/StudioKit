# Motion techniques in Roblox: checked facts and cost at scale

Purpose: the animator picks the cheapest technique that looks right (keyed clip on a rig, code-driven motion, physics constraint, texture or flipbook). This sheet holds what the docs say about each, with the line where it was read.

**How to read it.** `R/` = `knowledge/external/roblox-creator-docs/` (mirror revision 7400643, refreshed 2026-10-20, per `knowledge/reference/roblox/docs-map.md:6`). Verdicts: **confirmed** = the cited line says it; **partly** = the line says part of it, or says it with a limit; **unverified** = not found in the mirror, or only from a non-official source. Anything marked *inference* is the checker's reading, not a doc statement. Row ids are `RT<question>-<n>` so they do not collide with the `RT01-RT33` rows of `02-blender-roblox-process.md` (those are cited by their own ids). No Studio probe was run: every "cost" statement below is a doc statement, not a measurement.

Method note: the context packet could not be run (this role has no shell); inputs were read straight from the mirror, the kit files named in the brief, and two web searches (dates in the web section).

| RT3-10 | Sleep: a non-moving, non-accelerating assembly is not simulated. | RT3-11 | Assemblies on actuated joints (hinge/prismatic/cylindrical motor or servo, AlignPosition, AlignOrientation non-rigid, AnimationConstraint non-kinematic, LinearVelocity, AngularVelocity, winch rope) use a stricter sleep threshold so slow powered motion keeps going. | R/physics/sleep-system.md:108-110, 112-299 | confirmed | |
| RT3-12 | Things that wake an assembly: collision at over 1 stud/s, change of Anchored/CanCollide/Massless etc., impulses, any change to a Constraint on its attachments, change of `Workspace.GlobalWind`/Gravity/AirDensity/FluidForces, `Motor.CurrentAngle`, explosions. | R/physics/sleep-system.md:301-333 | confirmed | Writing `TargetAngle` every frame keeps the mechanism awake by that rule (*inference*); write it on state change only. |
| RT3-13 | Adaptive timestepping puts parts on 60/120/240 Hz islands; "up to 2.5 times" faster; complex mechanisms and fast parts go to 240 Hz; Fixed mode (240 Hz) suggested for racing, destruction, tanks. | R/physics/adaptive-timestepping.md:13-17, 59-63 | confirmed | |
| RT3-14 | Physics cost mitigations: anchor what needs no simulation, adaptive stepping, fewer constraints and joints per assembly, less self-collision. | R/performance-optimization/improve.md:170-181 | confirmed | |
| RT3-15 | Physics motion can differ per client / is non-deterministic. | no statement found; docs describe distributed ownership (RT3-08), simulation only in streamed areas (R/workspace/streaming/index.md:155), rollback and resimulation under Server Authority (streaming/index.md:155; R/projects/server-authority/techniques.md:122-126) | partly | The mirror never uses the words deterministic or non-deterministic (grep of physics/, workspace/, projects/, scripting/, studio/ found none). ## Technique choice facts

Label: D = documented (row id), I = inference.

- TC01 (D RT1-05, RT4-07): Anything cosmetic that is code-driven or clip-driven runs on the client. Server tweens replicate every frame; server-played clips replicate through the Animator.
- TC02 (D RT1-04, RT1-08): A tween is cheap to write and weak to interrupt: the second tween on a property cancels the first, and Cancel leaves the object mid-way. State the end pose and the interrupt rule in every motion spec.
- TC03 (D RT1-03, RT1-02): TweenInfo already gives 11 styles, 3 directions, repeat, reverse, delay. A door or lever with one start, one end and an ease needs nothing else.
- TC04 (D RT1-09): For many copies of one curve, a single shared loop with `TweenService:GetValue` (or `SmoothDamp` for a follower) avoids one Tween object per copy. (I) cost unmeasured.
- TC05 (D RT2-02, RT2-03): Code-moved props: anchor one root, weld or join the rest, move with `PivotTo`/CFrame. Do not move unanchored parts by CFrame unless physics is meant to fight back.
- TC06 (D RT2-05): `BulkMoveTo` is for a proven bottleneck, not a default. Ambient props start with single `PivotTo`/CFrame writes.
- TC07 (D RT2-08): For rigid hierarchies moved every frame, writing `Motor6D.Transform` in `PreSimulation` is the documented efficient path; an Animator on the same rig overwrites it.
- TC08 (D RT2-06): The docs name "animating parts yourself" as a task-scheduler overload risk. A per-object Heartbeat/PreRender loop for hundreds of props is the pattern to avoid: one loop per system.
- TC09 (D RT4-01, RT4-02): A mechanism that needs a keyed multi-part clip (drawbridge with chains, windmill with sails and gears, creature) = Motor6D rig plus `AnimationController` + `Animator`. A one-axis door, lever, lift needs no rigger step.
- TC10 (D RT4-07, RT4-08): Create the Animator on the client for decoration and distant props; its tracks then do not replicate, which is what is wanted.
- TC11 (D RT4-03, RT4-04): Bones deform one mesh (flag cloth, tree, tentacle); they do not change collision. Bone-only models under an AnimationController are likely but not shown in a sample: probe once.
- TC12 (D RT3-01, RT3-02, RT3-11): Hinge servo (door, gate), prismatic servo (lift, sliding door), motor modes (wheel, windmill, water wheel) are documented, take few properties and sleep when idle. A servo target written only on state change keeps cost near zero (I).
- TC13 (D RT3-08, RT3-07, RT3-15): Physics mechanisms are simulated by whoever owns them, so two players may see a free mechanism differently. Use constraints for feel on a mechanism the server owns, or for purely local decoration; do not use them where all players must see the same pose at the same time, unless the pose is driven by a servo target set from the server (I).
- TC14 (D RT3-12, RT3-11): Constraint edits, GlobalWind changes and unanchoring wake sleeping assemblies; set a servo target once per state change, not per frame.
- TC15 (D RT3-13, RT3-14): Few constraints per assembly; adaptive stepping stays on unless the mechanism is complex enough to need 240 Hz.
- TC16 (D RT5-05, RT1-11): Scrolling water, conveyor belt, lava, fog: `Texture` offset (tweened or stepped) on a BasePart face is the cheapest option and needs no rig. It does not bend a mesh.
- TC17 (D RT5-01, RT5-03): Small repeating animated effect (flame, spark, glow pulse, waving flag cloth as a billboard): flipbook particle. Up to 64 frames (8x8), at most 30 fps; the client may disable it on low-memory phones, so the object must still read without it.
- TC18 (D RT5-07, RT5-08, RT5-11): No animated mesh texture exists for general use. SurfaceAppearance is script-immutable; EditableImage on MeshPart.TextureContent is for single hero objects, needs a game setting and verified owner.
- TC19 (D RT6-01, RT6-04): Global wind will move grass, clouds, particles. Anything else (flags, trees, signs) needs its own motion; read wind from `Workspace.GlobalWind` only if the design wants wind-linked sway (I).
- TC20 (D RT7-05): Animated models do not get SLIM or imposter far-LOD. Plan for them to pop in at the streaming radius; keep the stand-in static if the far view matters.
- TC21 (D RT7-08, RT7-07): Many copies = many small streamed models, not a container; keep each prop's part count low.
- TC22 (D RT7-02, RT7-03): The engine throttles animation evaluation of remote models by itself (Workspace `ClientAnimatorThrottling`; `Animator.PreferLodEnabled`). Code that adds procedural offsets on top must read `EvaluationThrottled`.
- TC23 (D RT2-09, RT7-05): Client-set motion on server-made models is lost on stream-out; the motion script must restart on stream-in.
- TC24 (D RT7-10): Same mesh asset id on every copy; unique meshes cost draw calls (static or rigid-part props).
- TC25 (D RT4-10): Priorities matter only when layers share joints: Idle < Movement < Action; Core is Roblox's.
- TC26 (D RT7-09, I): Skinned decoration is documented by Roblox as a working pattern, but the instancing warning is old. The count of skinned copies near the camera is the first thing to measure.
- TC27 (D RT6-07, RT3-12): Do not run a fast GlobalWind gust loop in a world with many unanchored sleeping assemblies without a profile.
- TC28 (D RT1-13): The tween list has no Model pivot: moving a whole Model is `PivotTo` driven by a loop or by a tween of a helper value (I).
- TC29 (D RT7-14, RT6-03): Reduced-motion exists as a player setting (grass honours it). Ambient loops should have a still or slow variant (design choice).
- TC30 (D RT3-09): Anything a client owns can be faked; a trap's damage cannot read the visual mechanism's state from the client.
