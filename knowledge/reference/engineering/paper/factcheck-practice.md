# Engineering paper: fact-check of the practice claims (J010-T10)

Scope: Anthropic / Claude Code / Opus 5.5 behaviour, agent-eval practice, code-review practice, test tools, other studios' practice. The Luau and engine claims are the other fact-checker's.

## How I checked

- Every page was read on 2026-10-21 through WebFetch (a small model summarises the page; I asked for the exact sentence each time). GitHub dates come from `api.github.com` (full ISO timestamps), which settles the yearless dates the paper could not read.
- Living documentation has no publication date. I write "living page, read 2026-10-21". Dated posts show their own date.
- Rule from the paper (line 19): results on models released before 2026-09-01 are not evidence for this stack. I mark such claims `older-model-only`.
- Opus 5.5 was released 2026-09-22 (F11). Opus 5, Opus 4.5 and 4.6 pages are pre-cutoff.
- Verdict words: confirmed, corrected, partly, unverified, contradicted, outdated, older-model-only. A verdict on an opinion (Q00) means "Anthropic's own guidance points the same way", not "proven".
- A fetch summariser can drop words. Where an exact wording decides an eval design, the cell says so.
- Kit files were read, not edited.

## 3. Use in skills and evals

1. Cite F25 (2026-09-28) for the hidden-test split: random train and held-out split, the tuner reads train failures only, answers kept out of reach, a change counts only if held-out improves too, results with a confidence interval, noise smaller than the smallest improvement you act on. Cite A09 (2026-01-09) for deterministic graders first, calibrated LLM graders, outcome grading, bypass-resistant graders, trials from a clean state, both-sided cases, pass@k versus pass^k, 20-50 real-failure tasks as a start, and reading transcripts.
2. State the limits of every trial and print them with the result: model id, effort, time cap, memory, tools (A12: different budgets are not the same test). Frontmatter `effort:` on a role is overridden by `CLAUDE_CODE_EFFORT_LEVEL` and by an explicit `/effort` (https://code.claude.com/docs/en/sub-agents, living page); record the effort that actually ran. Treat score gaps under about 3 points as noise until limits match (A12 advice).
3. Define the first-try rate as "first submitted candidate before hidden-test feedback" (pass@1) and report pass^k for reliability. Never say it equals the 39 of 40 or 54.6% figures (F06, F07).
4. Reviewer eval: use planted faults plus clean controls (A09 both-sided cases). Judge on recall of the critical faults and false blockers, not on the number of comments or rounds (F27, F29).
5. Use Open Cloud Luau Execution with the real limits: 5 minutes a task, 5 task creations a minute, no physics, no auto-run scripts (F38). Multi-client tests need Studio open (StudioTestService has Plugin Security); say which test needed Studio.
6. Effort: start at medium; use high where verification matters or edge cases are common (Anthropic 2026-09-25); raise only after a local comparison (F04).
7. A hosted or local review comment is advice. The gate is `tools/verify` and the protected acceptance run (F15, F17).
8. Bug fixes start with a failing test: supported as practice by Wube (F13), by Anthropic's best-practices page ("write a failing test that reproduces the issue, then fix it"), not as a measured gain.
