# What the 14 Riot transcripts teach the studio

Paraphrased. `R05:170` = line 170 of that transcript. Every line was read by a reader agent; the lead spot-read the collaboration, review and order sections. All episodes are short live demos of work that normally takes weeks, so the **order** of steps is real but the timing is compressed (extract C caveats, E caveats). **None of them names a sign-off chain, gate owners or round counts** (A §5, E §C7): the studio's gates come from the papers and the kit, not from Riot.

## 2. How work moves between crafts (orchestration evidence)
| Finding | Evidence |
| --- | --- |
| A shared target experience comes first and is kept all the way; art is not downstream of design; mismatches happen when parallel crafts lack one written target (Shen: tank to design, assassin to art) | R00:5280-5308, R00:5393-5423 |
| Constraints are handed to concept before drawing: mechanics, numbers, camera, lore; rig joints and moving parts are listed before the design | R00:616-662; R01:76-112 |
| Constraint owners speak early: animators at concept (feasible / more possible), VFX tells concept up front where it will diverge, sound can refuse a new surface material for time | R04:184-190; R06:36-37; R02:472-480 |
| Costly downstream parts are decided early: capes and cloth cost animators months; parts kept off joints; rig-costly shapes flagged with a cheap fallback | R11:87-129, R11:305-312; R03:908-928 |
| The modeler must know the rig before modelling (a mouth modelled shut broke animation) | R03:864-900 |
| Timing spine: design sets each action's frame lengths; the animator sets the beats; VFX runs partnered, slightly behind; sound places frame-accurate markers on picture events | R04:164-180; R07:211-215 |
| Music and sound are planned and mixed together early so notes come early | R07:198-204 |
| Gameplay owns layout: environment stays inside the approved greybox on a shared grid; art starts after the designer approves the blockout | R02:454-460; R09:668-680 |
| An embedded designer checks environment placement, materials, set dressing and VFX placement during the work; without check-ins the result is "mediocre" | R02:460-470; R09:596-622, R09:806-818, R09:1068-1080 |
| Upstream changes happen by asking (taller landmark, separate sound zone), never silently | R09:354-358, R09:596-604, R09:848-856 |
| Motion problems send the model back upstream through rigger and animator | R00:1540-1562 |
| The concept owner stays on through production to answer each craft's questions | R01:248-256 |
| Illustration and branding feed each other (a circle motif became the update's shape language) | R05:395-423 |
| One key art becomes a family of 20-50 assets; it is delivered layered | R05:732-797, R05:868-872 |
| Gate rhythms that exist: TFT splash thumbnail → green light (big shapes stop moving, 1.5-2 weeks) → render → polish; TFT environment blockout → early production (open to feedback) → polish (big feedback waits for next release) | R08:656-712; R13:663-697 |
| Review style: paint-over on the builder's screenshot; feedback after 3D answered in 2D first because 2D is cheaper | R03:790-806; R13:205-219, R13:826-832 |
| Done = the notes start to repeat; a producer or outside eye calls done | R08:814-820; R04:848-856 |
| Ties go back to the brief's strategy; if every option meets it, the artist decides the last few percent | R05:160-164, R05:834-846 |
| Present 2-3 directions and say which one the team prefers; show them rough | R05:170-176; R08:554-566 |
| Consensus is not the goal: aim at the target audience | R00:1036-1056 |

## 3. Principles every craft shares
| Principle | Evidence |
| --- | --- |
| Clarity, satisfaction, style are art's three jobs; the most important thing is the easiest to see; to focus one thing, calm the rest | R00:86-285 |
| Detail is a budget: clump detail next to rest areas | R00:346-378; R02:490-500; R09:946-952; R13:961-980 |
| Judge at the real camera, size and context (top-down unit, shop slot, first-person, in-game, full mix), never as a beauty shot | R01:271-275; R03:198-208; R08:134-146; R06:65-68; R07:587-590 |
| Big to small: silhouette → value → light and colour → detail; bring every part up together | R05:465-482; R03:220-232; R12:282-303 |
| Grey value check before colour | R12:284-285; R13:424-438 |
| Value ladder across crafts: UI and VFX get the full range, characters less, environment a clamped band; red reserved for danger | R02:806-818; R13:749-790; R02:204-208 |
| References first and heavy; mix existing art with real-world sources; never stop at existing art (anti-copying) | R08:148-198; R00:684-716 |
| Several distinct rough options; the first idea is often the expected default | R08:292-294, R08:620-634; R00:740-760 |
| Keep identity anchors (2-3 per view) when making a variant | R12:73-81; R11:214-226; R10:117-130 |
| Act the moment out before building (motion, VFX, sound) | R04:632-636; R06:218-222; R07:539-546 |
| Reuse the shared library before making new | R06:41-44; R07:113-118 |
| Take a note for its problem, not its suggested fix; ask "what are you trying to do?" | R00:2175-2201, R00:2457-2497 |
| Close doors: once decided, do not reopen | R00:840-858 |
| Delete and redo without attachment; expect 3-5 tries | R04:420-432; R00:3316-3336 |

## 4. Lessons per role (for the workflow books)
| Role | Lessons (strongest first) | Evidence |
| --- | --- | --- |
| orchestrator | name the type of fun in every brief; constraints in the brief before any image; ask the owner one goal-tied question, not "do you like it?"; show early and rough; record closed doors; route notes as problems, not fixes | R00:5213-5271, R00:584-662, R00:860-884, R00:840-858, R00:2175-2201 |
| game-designer | own layout, cover and blocking surfaces; sit "embedded" with the environment build; mechanics and art must imply the same theme; prototype the simplest version and play it with someone; curate ideas from all roles | R02:454-470; R09:606-622; R00:5393-5423, R00:5767-5825 |
| art-director | 2-3 directions with a stated preference; identity anchors list; answer material intent for every reference image; give paint-over notes; judge silhouette and design, not endless colour debate; value ladder across crafts | R05:170-176; R12:73-81; R03:270-276, R03:790-806; R12:432-439; R02:806-818 |
| film-director | establishing composition; light as focus and decoy; previs-approved shots become the shot plan; mix picture, VFX and sound early | R00:1887-1927; K6; R07:198-204 |
| environment-designer | stay inside the greybox; player-size reference in every space; detail by camera distance and player speed; story by climate, age and wear; lighting and polish after playtests; make its own rough concept under the art bible when none exists | R02:454-518, R02:396-412; R00:1951-1987, R00:1781-1785; R13:583-595 |
| modeler | know the rig first; overlay on the base mesh; edge loops for deformation; light baked into value (lit tops, darker lower body); review at game camera on the real background; define done before starting | R03:864-900, R03:166-168, R03:740-744, R03:234-238, R03:436-448 |
| character-rigger | rigs bend with no odd results, intuitive controls, foot-plant and follow switches; triage notes that block motion back to the modeler | R00:2399-2437, R00:1540-1562 |
| animator (planned) | clear actions, consistent physics, personality from 2-4 adjectives; weight transfer; no twinning; root cadence and poses first, hair and face last; silhouette from the game camera; plan the state machine with builders | R00:2941-3301; R04:456-474, R04:360-366, R04:970-982, R04:702-708 |
| vfx-designer | primary, secondary, tertiary reads; routine effects small and short, never hiding information players need; brightest point where the eye must go, pure white and black saved; beginning, middle, end around the hit frame; colour next to the caster's; game-wide shape meanings | R00:3552-3832; R06:49-80, R06:131-174, R06:204-210 |
| sound-designer | each sound is a cue, feedback or emotion; picture sync markers before design; stages load, charge, shot, travel, impact, tail; clean tonal layers apart from mechanical layers; shared terms for review (ADSR, attenuation, EQ, reverb); reverb shows the space | R00:4059-4349; R07:211-222, R07:322-325 |
| ui-ux-designer | UX flow before UI; core theme and strict rules before screens; function before polish; five motion goals; proximity carries meaning; phone-first density | R00:4573-4949 |
| marketing | 3-5 rough thumbnails; green light then the big shapes stop moving; the brief's strategy names the hero; layered delivery; plan the crops; same face and posture in every product; check on a second calibrated screen | R05:144-176, R05:732-872; R08:656-712, R08:743-763 |
| architect / feature-builder | ask what the request is for before building; sounds and VFX hang on named game events, so builders provide the hooks; automate repeated steps | R00:2457-2497, R00:4329-4349, R00:2499-2541 |

## 5. Gaps
- No sign-off chain, gate owner or round count in any transcript (A §5; E §C7; D §7).
- No explicit VFX ↔ sound sync negotiation and no animation event markers handed to VFX or sound in a game (E §C6): the shared event timeline in `design-jobtypes.md` is an inference from R04 and R07 plus P1:169.
- R07 is film sound: its picture-led timing fits cutscenes directly and gameplay only by analogy (E caveat).
