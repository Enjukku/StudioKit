## Findings

### R05-F01 The brief decides; the product is the hero
- principle: Key art serves what the product is doing (new map, new character, new skins). Start from that strategy, and make the launched thing the hero of the composition. When options are hard to pick, go back to the strategy.
- why: The picture's job is to make the player want the new thing; a beautiful picture that hides it fails.
- apply: Every marketing image brief (icon, thumbnail, update art) names the one thing being launched and makes it the largest/clearest element. Reference-image prompts state the hero object first. With no brief, the agents write one ("we are our own brand managers").
- check: In the 16:9 thumbnail at player size (thumb_check.py), ask "what is this update about?" — the hero must be the first thing seen and the largest readable element.
- mistake: Choosing between equally good options by taste instead of by the brief (R05:162-164).
- example: For a new map, "that map has got to be almost like the hero of the composition" (R05:164).
- roblox_fit: Applies to update thumbnails and event icons; thumbnails display at 16:9, ideally 1920x1080 (knowledge/external/roblox-creator-docs/production/publishing/thumbnails.md:54).
- roles: marketing, art-director, orchestrator, live-ops-designer, film-director, reference-images
- topic: references-ideation (secondary: composition-focus, new:asset-kit)

### R05-F02 Brand pattern plus one unique twist (names and type)
- principle: Episode names follow one fixed pattern (all end in "-tion": Ignition, Evolution, Revelation → Resurrection). Logo type stays inside the brand fonts and lock-up, then gets one modification (grit, custom line art) unique to the episode: "as close as possible to the brand but still feel unique".
- why: Players recognise the series instantly, and still see that something is new.
- apply: For update/event names and logos, keep a naming pattern and brand font set in the game profile; each event varies one property (texture, colour, an ornament) on the Figma logo component, not a new font.
- check: Put the new logo beside the previous two; it must read as the same game at thumbnail size and differ in exactly one visible property.
- mistake: A new font or a free-form name per event that breaks the series [inference].
- example: "Resurrection" fits the -tion convention; bold VALORANT lock-up with added grit for Halloween (R05:391-395).
- roblox_fit: Logos and titles on Roblox thumbnails and in-game UI must survive phone-size viewing [unverified].
- roles: marketing, live-ops-designer, ui-ux-designer, art-director

### R05-F03 Keywords to visual facts
- principle: Exploration starts by searching each keyword and writing down what it gives visually: "apocalypse" → dust colours and abandoned city; "survivors" → serious, worn expressions; "zombie" → grey and green. These facts feed the composition sketches.
- why: Keywords alone are vague; concrete colour keys, settings and expressions make the idea drawable and shared.
- apply: Before the first ChatGPT image prompt, the agent writes a keyword table: keyword → colour key, setting, expression/pose, prop. Prompts are built from that table. Existing game assets can be the setting (they named the Fracture map for overgrown, crumbly buildings).
- check: Every element in the first rough maps to a row in the keyword table; no row is missing from the image.
- mistake: Starting generic compositions with no visual research (Su Ke expects a generic first pass and fixes it with keywords, R05:91-95).
- example: Apocalypse = dust colours; survivors = serious faces; zombies = grey/green (R05:107-111).
- roblox_fit: Reuse existing game maps and assets as settings for marketing art; no engine limits involved.
- roles: reference-images, art-director, marketing, environment-designer, modeler, vfx-designer
- topic: references-ideation (secondary: light-colour)

### R05-F04 Palette = theme colour + brand colour + complementary accent
- principle: Build the palette from the theme words (Halloween orange and grey; zombie grey/green; poison "corrupted" colours), keep the iconic brand colour (VALORANT red), and bring the complementary colour in through design elements. A scene can commit to one dominant hue ("the whole scene is gonna be really green").
- why: A dominant hue sets the mood at a glance; the brand colour keeps identity; the complement gives contrast.
- apply: In the art bible palette, name roles: dominant (theme), brand, accent (complement). Event art uses a dominant hue for the whole scene. In Studio, ColorCorrectionEffect TintColor/Saturation can push a scene toward the dominant hue (knowledge/external/roblox-creator-docs/environment/post-processing-effects.md:83-85).
- check: look_check.py palette: one dominant hue family covers most of the frame; brand colour and the complement each appear and are not equal in area.
- mistake: Equal amounts of many hues so no mood reads [inference].
- example: Viper scene "really green"; orange complement "comes in from the design elements" (R05:113, R05:231).
- roblox_fit: Post effects are global per camera; tint for a mood must not hurt gameplay reads [inference].
- roles: art-director, marketing, environment-designer, vfx-designer, ui-ux-designer, reference-images
- topic: light-colour (secondary: style-identity)

### R05-F05 Moodboard a genre for tone
- principle: When the tone is open, moodboard the genre the piece imitates (retro horror / B-movie posters) to decide how serious or "cheesy" it is, and read the board for recurring colours (lots of orange).
- why: A genre carries a known tone the audience already reads; looking at many examples shows the shared traits.
- apply: Reference-images agent builds a moodboard sheet from a named genre and lists 3-5 traits that repeat across it (colour, layout, type, faces). Do not copy one poster.
- check: The traits list exists and the rough uses at least the main ones; no single reference is recognisable in the output.
- mistake: Not deciding tone early ("not sure how serious or light-hearted it is yet", R05:36).
- example: Retro horror posters (Creature from the Black Lagoon, Evil Dead, etc.) gave a B-movie cheesy tone and orange colours (R05:115-141).
- roblox_fit: No engine impact; use for event key art and thumbnails.

### R05-F06 Two or three distinct directions, then variations
- principle: Thumbnailing = brainstorm right after exploration. Make about 3 clearly different directions (classic survivors; horror big heads + giant silhouette; survivors fighting), explore "2 or 3 options, solid, distinct directions", then go down the variation route on the chosen one. Get the first idea out first.
- why: Distinct options test different ideas; variations of one idea only test details. Early cheap options keep choice open.
- apply: Reference-images produces 3 distinct thumbnails (different layout, story or camera, not colour variants) before any polish; variations only after the pick. Default 3 (source number).
- check: Black-fill the 3 thumbnails: their silhouettes/layouts must differ clearly; if two look the same in silhouette, they are one direction.
- mistake: Presenting variations of one idea as different options [inference].
- example: Three thumbnails, then two Sage variants (comedy nervous vs epic evil) (R05:146-156, R05:278-283).
- roblox_fit: Same for icons, thumbnails, UI moods and level layouts.
- roles: reference-images, art-director, marketing, modeler, environment-designer, ui-ux-designer, game-designer

### R05-F07 Group silhouette and back-to-back staging
- principle: A team drawn as a group is "a different silhouette" from a single figure; silhouetted survivors back-to-back, surrounded by small zombies, tells the survival story in one read.
- why: The outer shape of the group carries the idea before any face does; encirclement reads as danger.
- apply: For group shots (marketing art, cutscene frames, lobby poses) design the group's combined silhouette; surround with smaller repeated threat shapes.
- check: Black-fill the group: the combined shape reads as a team and the threat ring reads around it at thumbnail size.
- mistake: Characters lined up with no group shape [inference].
- example: "The sole survivors" silhouetted fighting zombies; add tiny zombies coming toward them (R05:247-259).
- roblox_fit: For top-down or third-person gameplay, enemy encirclement reads from shape and count; keep particle/NPC counts within budget [unverified].

### R05-F08 Two choice points; always state your pick
- principle: Stakeholders choose twice: first from the thumbnail silhouettes, later the finished treatment. Give options and always add the makers' preference ("personally, we think this one is gonna work better").
- why: Picking at silhouette stage is cheap; a stated preference helps people who find all options good.
- apply: Owner gates on art: G1 shows silhouette/thumbnail options with one recommendation; the final gate shows treatment options with one recommendation.
- check: Every options sheet sent to the owner has exactly one marked recommendation with a reason tied to the brief.
- mistake: "Good luck, choose the best one" — options with no recommendation (R05:162, R05:840).
- example: Sketches chosen by silhouette; treatments from Brandon chosen at the end (R05:166-169).
- roblox_fit: none.

### R05-F09 Pose against the character's trait
- principle: Comedy comes from contradiction: a known tough guy (Brimstone) running away "with fear in his eyes".
- why: The viewer knows the character's normal attitude, so the opposite reads as a joke and a story.
- apply: For emotes, event poses and promo art, list the character's known trait and pick a pose that clearly contradicts it when the tone is comic.
- check: Without text, a viewer who knows the character reads the joke; the fear must read in pose (running, looking back), not only the face, at game camera distance.
- mistake: not stated.
- example: Brimstone running from zombies (R05:221-225).
- roblox_fit: At phone size faces are tiny; the contradiction must read through body pose [inference].
- roles: animator, film-director, marketing, art-director

### R05-F10 Giant background figure for scale and threat
- principle: A giant figure in the background (Viper, back to camera, side view) above a crowd of small zombies and small fleeing protagonists makes the threat feel huge; the turned back "adds a little to it".
- why: Scale contrast between background and foreground reads as power; a back-turned pose is mysterious.
- apply: For boss reveals, event art and cutscene shots, stage the threat oversized behind small heroes; keep the heroes in the foreground.
- check: Height ratio of background figure to foreground heroes is large and obvious in a capture; both read in black-fill.
- mistake: not stated.
- example: Giant Viper with green smoke, zombies going for her, heroes running (R05:213-231); Brandon suggests big Viper or Sage behind the survivors (R05:249-251).
- roblox_fit: In game, use a fixed camera or cutscene to get this scale shot; avoid huge parts that block the play camera [inference].

### R05-F12 Story premise first; signature ability pose

### R05-F15 Silhouette first, then light, detail last
- principle: Focus on silhouettes first and ignore detail; lock the pose with simple shapes; once happy, add rough lighting (general side light); the face has nothing yet — "I can always add details later". If a pose fails, little time was lost.
- why: Big decisions are cheap to change at shape stage; detail spent on a wrong pose is wasted.
- apply: Blender blockouts and ChatGPT roughs are judged in flat shapes first; only after the silhouette passes, light; detail and textures last. Fix proportions here (e.g. Gekko "too tall", made shorter, R05:459).
- check: Black-fill silhouette check passes before any lighting/detail work is accepted; then a grayscale render shows one clear light direction.
- mistake: Polishing detail before the pose is locked [inference from R05:475-481].
- example: Shapes to lock Brimstone's pose; side light added roughly (R05:465-477).
- roblox_fit: Same order works for blockout parts in Studio before MeshParts [inference].

### R05-F17 Follow the happy misread
- principle: When a rough shape reads as something else that also works (zombies reading as graves), consider changing the plan: foreground graves, zombies moved to the background.
- why: The viewer's first read is the truth; use it rather than fight it.
- apply: In review, write what each shape reads as at first glance; if the read is good, adopt it; if bad, fix the shape.
- check: Cold read of a capture: list what each main shape looks like; compare with intent.
- mistake: Forcing a shape to mean what it does not read as [inference].
- example: Foreground zombies → graveyard (R05:489-493, R05:524-527).
