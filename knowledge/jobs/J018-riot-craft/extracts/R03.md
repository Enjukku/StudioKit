## Findings

### R03-F01 Block material regions first
- principle: Before shading, split the model into flat colour regions per material (red, blue, white, gold). Then shading can be fast and loose without messy edges.
- why: Clean material boundaries are decided once; later passes only change value inside a region, so the read of "which part is which material" stays clean.
- apply: In Blender, assign one material slot (or one ID colour) per material before any detail; in Roblox keep one MeshPart/SurfaceAppearance region or Part colour per material. For reference images, ask the image model for a flat-colour "material ID" version of the concept sheet. [inference]
- check: Render flat (emission/unlit) at the game camera: each material region is one flat colour with clean edges; count the regions against the concept's materials.
- mistake: Painting detail before boundaries are set, so edges get "messy" (R03:74).
- example: Caitlyn's red, blue, white and gold masked out before painting (R03:72-74).
- roblox_fit: Same in Roblox; fewer material regions also mean fewer textures/materials to load on phones [inference]. SurfaceAppearance adds PBR maps to a MeshPart (knowledge/external/roblox-creator-docs/art/modeling/surface-appearance.md:40).
- roles: modeler, art-director, reference-images
- topic: materials-detail (secondary: pipeline-tech)
- lines: R03:70-76

### R03-F02 Read the concept's intent; start from local colour
- principle: Do not copy the concept back and forth stroke by stroke ("bobblehead"); understand what it is trying to say and translate that. Start each material from its local colour: its colour with no light on it (an apple's local colour is red).
- why: A 3D model seen from many angles cannot match a 2D image pixel for pixel; the intent survives the translation, the pixels do not. Local colour is the anchor that shadows and highlights are shifted from (see F34).
- apply: Before modelling, write 3-5 lines of "concept intent" (who, mood, key reads, materials) from the approved reference image; set each material's base colour to its local colour, unlit.
- check: Compare a render at the game camera with the concept at the same size: do the intent lines hold? Does each material's flat base colour match the concept's mid-tone, not its shadow or highlight?
- mistake: Looking back and forth constantly and copying surface detail instead of intent (R03:82-86).
- example: Base colours laid down first, "without any lighting" (R03:80).
- roblox_fit: Same.
- roles: modeler, art-director, character-rigger, reference-images
- topic: references-ideation (secondary: light-colour)
- lines: R03:80-86, R03:782-789

### R03-F03 Light comes from above
- principle: League lighting is top-down: everything facing up is lit, everything facing the other way is darkened. Paint and judge every shape as lit from above.
- why: A consistent single light direction lets the eye read each shape's form; it matches how the world lights the character, so it sits in the scene.
- apply: In Blender review renders, use one key light from above (sun at a high angle) matching the game's Lighting; in Roblox set Lighting so the sun is high for the review captures. Painted-in shading on hand-painted textures should also follow a top light. [inference]
- check: Grayscale render at the game camera: up-facing planes (shoulders, hat top, head) are the brightest values; under-sides (under the hat brim, under arms, below waist) darker.
- mistake: not stated (implied: shading with no single light logic).
- example: "everything facing upwards is gonna be lit" (R03:97-98); learned in the internship: light from the top, push back below the waist (R03:1058-1061).
- roblox_fit: Roblox lighting is dynamic; sun height comes from Lighting.ClockTime (knowledge/external/roblox-creator-docs/environment/lighting.md:175-179). Strong painted shading can fight dynamic light, so keep painted AO soft and let the engine light the rest [inference]. Roblox cameras are usually third-person behind the character, less top-down than League, so up-facing still reads but the back/sides are seen more [inference].
- roles: modeler, art-director, environment-designer, vfx-designer, reference-images
- topic: light-colour (secondary: value-contrast)

### R03-F04 Fail fast in early passes
- principle: Early passes are not the final product: experiment, make mistakes, keep it loose. Fear of mistakes means nothing interesting gets made. "Fail fast and learn quickly."
- why: Cheap early exploration finds the good accidents and the dead ends before effort is sunk.
- apply: Make several rough options (reference images, blockouts, rough clips) quickly before refining one; label rough passes as rough.
- check: Did the work show more than one rough option or pass before polish? Is any part polished while the whole is still rough?
- mistake: Being "too scared of making mistakes" (R03:102-104).
- example: Loose AO painting on Caitlyn's hair (R03:94-106).
- roblox_fit: Same.
- roles: animator, modeler, art-director, vfx-designer, sound-designer, ui-ux-designer, environment-designer, reference-images, reviewer
- topic: critique-feedback (secondary: references-ideation)
- lines: R03:100-106, R03:128-132

### R03-F05 Rich high form, budgeted game mesh with deform loops
- principle: Make the organic form at high detail first (it keeps the natural subtlety of the body), then build a low-poly game mesh over it. The game mesh is capped (League skin: 15K tris at most) and its quads sit where the body bends so it deforms right.
- why: Modelling low first "can distort the human aspect"; the cap keeps the game running; loop placement decides whether elbows and knees fold cleanly for animators.
- apply: In Blender: block and refine the form (or start from a Tripo mesh as the "high"), then retopologise; set a per-character triangle budget in the brief (source default for a hero character: 15,000 tris); put edge loops at elbows, knees, shoulders, mouth and eyes; UV after.
- check: Count triangles in Blender; inspect loops at every joint; bend test the joints with the rig (see F12, F37).
- mistake: Modelling low-poly first and losing the natural human form (R03:153-155).
- example: ZBrush high-poly → Maya retopo → UV → 3D-Coat paint (R03:148-170).
- roblox_fit: Roblox caps a single mesh at 20,000 triangles (knowledge/external/roblox-creator-docs/art/modeling/specifications.md:34); a Roblox tutorial character uses under 10,000 per part (knowledge/external/roblox-creator-docs/resources/beyond-the-dark/custom-characters.md:89). With many players on screen on phones, a lower budget than League's 15K is a sound default [inference]. Mouth and eye loops: knowledge/external/roblox-creator-docs/art/characters/creating/modeling-best-practices.md:69,81.
- roles: modeler, character-rigger, animator
- topic: pipeline-tech (secondary: shape-silhouette)
- lines: R03:148-168, R03:170-176

### R03-F06 Form shadows make a still object read as 3D
- principle: The first painting pass on flat colour is ambient occlusion / form shadows. A player looking at a still or small character cannot tell it is 3D unless it has form shadows. Learning to build form from flat colour (not only from bakes) teaches where they belong.
- why: We read depth from shading; turning the model is not available to a player at a glance.
- apply: In Blender, bake AO and multiply it softly into the base colour (or SurfaceAppearance ColorMap) as a starting point; then adjust by hand logic (F21, F24, F25). For icons and thumbnails, make sure renders keep form shadows.
- check: Grayscale capture at game size with the model not moving: can you tell the forms are round/convex/concave without rotating? Flat-looking areas fail.
- mistake: Relying on the turnable 3D view and leaving the texture flat (R03:182-186).
- example: AO pass on Caitlyn's flat colours (R03:178-186).
- roblox_fit: Roblox renders its own shadows, but small detail AO is not computed for small forms; painted/baked AO in the colour map still helps at phone size [inference] [unverified].
- roles: modeler, art-director, environment-designer, ui-ux-designer, marketing, reference-images
- topic: value-contrast (secondary: materials-detail)
- lines: R03:178-186, R03:88-94

### R03-F07 Personality drives the features
- principle: Keep the character's personality in mind while making every feature: Caitlyn is elegant (willowy, tallish, upper-class) and also deadly (scary sharpshooter), so features are striking and sharp, not cute.
- why: Players read personality from proportions and features before any line of dialogue.
- apply: Write a two-word character tension in the brief (e.g. "elegant + deadly") and check each choice (proportions, face, pose, sound, idle animation) against both words.
- check: Show the render at game size to a reviewer agent with no context: do the two words come back?
- mistake: Defaulting to a generic or cute face on a serious character (R03:974-976 with F17).
- example: "a serious character... some attitude, sharper, dangerous features" (R03:974-976).
- roblox_fit: Same; on a phone, proportions carry more than face detail [inference].
- roles: modeler, art-director, animator, sound-designer, reference-images

### R03-F08 Work from far away; first read
- principle: Do not work zoomed in. Keep a far-away view; the first read must hold when you squint ("really bad vision"): it looks human, the coat reads as a coat. Characters are small in game, so the first read is the most important thing.
- why: Detail done close up is invisible at game size; what the player sees is the big-shape read.
- apply: Do every review render at the game camera distance and phone size first; only zoom in after the far read passes. She paints even shading from far away (R03:1034-1036).
- check: tools/art/look_check.py thumbnail/value view and a blurred (squint) capture at the game camera: can you name the character and each major garment?
- mistake: "working really close to the character", focusing on face, bow or golds and losing the far read (R03:198-206) — the mistake she sees most in new character artists.
- example: Squint test: still a human, coat still a coat (R03:202-204).
- roblox_fit: Even more important on a phone with a third-person camera and many players on screen [inference].
- roles: modeler, art-director, reviewer, qa-lead, vfx-designer, ui-ux-designer, marketing, environment-designer, reference-images

### R03-F09 Identifying points and the 3D form read
- principle: Each character has identifying points (Caitlyn: always a hat, a giant rifle, long legs, the collar). In 3D the first read is the shape itself: what pops out and what is concave, made clear or even over-emphasised.
- why: Recognition comes from a few signature shapes; exaggerating the convex/concave read survives distance.
- apply: List 3-4 identifying points per character in the brief; make them the largest, clearest shapes; push form contrast beyond realism.
- check: Black-fill silhouette and grayscale at the game camera: is each identifying point visible? Do convex parts carry highlights and concave parts shadow?
- mistake: not stated.
- example: Hat, rifle, long legs, collar (R03:210-212).
- roblox_fit: Same; keep identifying points readable from behind for third-person cameras [inference].
- roles: modeler, art-director, character-rigger, animator, reference-images, marketing
- topic: shape-silhouette (secondary: exaggeration, character-design)

### R03-F10 Even pace across the whole character
- principle: Bring every part of the character forward at the same pace. Working the face a lot and leaving the rest untouched makes the character feel incomplete.
- why: The whole read is judged together; an even pass gives a strong first read early and confidence that it is "going somewhere".
- apply: Plan passes over the whole asset (blockout all → base colour all → AO all → detail all); do not polish one part ahead.
- check: Each review render: is any region at a clearly higher finish than the rest?
- mistake: "work on the face a lot and then everything else was just kind of left untouched" (R03:220-222).
- example: Her own early habit, corrected through experience (R03:220-226).
- roblox_fit: Same; also applies to environments and UI screens [inference].
- roles: modeler, art-director, environment-designer, ui-ux-designer, reviewer

### R03-F11 Compare against the game map
- principle: Keep the actual game map in the background while painting so you can compare colours and make sure the character stands out and still belongs to the world.
- why: A character judged on a neutral grey background can vanish or clash in the real scene.
- apply: In Blender, put a capture of the game's map (or the art-bible environment anchor) behind the character for review renders; in Studio, review the character standing in the real map.
- check: tools/art/look_check.py value/palette on a capture in the real map: does the character separate from the ground in value and saturation? Does its palette still fit the art bible?
- mistake: Judging only against an empty background [inference].
- example: League map behind Caitlyn while painting (R03:234-240).
- roblox_fit: Same; test in the brightest and darkest areas of the map [inference].
- roles: modeler, art-director, environment-designer, vfx-designer, reviewer, level-design

### R03-F12 Build for the next craft
- principle: The biggest constraint for a character artist: elbows must fold correctly, no strange points or unnatural folds, and the model must not be a pain for the next people in the pipeline (rigging, animation). Ask them their needs; do not insist "this is for my craft".
- why: A model that deforms badly breaks every animation; fixing it after rigging is expensive.
- apply: Before modelling, read the rig sheet (rig-pipeline) and ask the rigger for joint positions, cut points and parts that move; record the agreed points in the contract.
- check: Pose the mesh at extremes (full elbow bend, knee bend, arm raised) with a test rig: no spikes, collapses or interpenetration.
- mistake: Working only for your own craft's look (R03:266-268).
- example: Elbows folding "like a box with many loops" (R03:252-256).
- roblox_fit: Same; Roblox characters use Bones with skinned MeshParts or Motor6D rigid parts (see rigging-design skill) [unverified here].
- roles: modeler, character-rigger, animator, orchestrator
- topic: pipeline-tech (secondary: new:cross-craft-cohesion)
- lines: R03:248-270, R03:276-286

### R03-F13 Ask the material intent
- principle: Find out what the concept means by each material: is the gold vest gold armour, or shiny reflective cloth? Is the coat silky or velvety? Get references for it.
- why: The same colour can be very different materials; guessing wrong changes the whole read and the rig (stiff vs cloth).
- apply: The brief or reference sheet lists each material by name and type (metal, cloth type, leather, skin) with a real-world reference; if missing, ask the art director before texturing.
- check: Each material region in the render reads as the named material at game size (F19).
- mistake: Guessing material intent [inference].
- example: "Did they really want it to be gold armor or... a shiny cloth" (R03:272-276); "Is this material more silky? ...more velvety?" (R03:820-822).
- roblox_fit: Roblox MaterialVariant/SurfaceAppearance choices follow the same decision [inference].
- roles: modeler, art-director, reference-images, vfx-designer
- topic: references-ideation (secondary: materials-detail)
- lines: R03:270-276, R03:818-825

### R03-F14 Eyes in early
- principle: Put the eyes (irises) in early, even as temporary, because the eyes make it read as a person with a personality you can relate to.
- why: Faces are read through the eyes first; without them, the character feels dead and judgement of the rest is off.
- apply: Add eye placeholders in the first texture or blockout pass.
- check: Early review render: are eyes present and placed?
- mistake: not stated.
- example: Temporary irises on Caitlyn (R03:286-292).

### R03-F15 Brows, face structure and nose carry identity
- principle: Eyebrows and facial structure are among the most identifying parts of any character. Brow thickness changes the face silhouette a lot (Goku is known by eyebrows and hair shape). A sharp, serious character needs a sharper, downward nose, not a button nose.
- why: Brows are very expressive and big-contrast; face shapes encode personality.
- apply: Specify brow thickness/angle and nose shape in the character sheet; exaggerate brow shape for small screens.
- check: Close and game-size render of the head: can a reviewer identify the character from the head silhouette and brows alone?
- mistake: Using a cute default face (button nose) for a sharp character (R03:388-390).
- example: Caitlyn sharper nose vs Lux's button nose (R03:388-390); Goku's brows and hair (R03:972).
- roblox_fit: Same; on phones only big face shapes survive [inference].
- roles: modeler, art-director, reference-images, animator
- topic: character-design (secondary: shape-silhouette)
- lines: R03:360-366, R03:388-390, R03:968-974

### R03-F16 Variants keep the identity and add something fresh
- principle: A skin reimagines a beloved character (bubbly, pop star, cyborg) but must keep the key features that make them that character ("What makes them Garen?") while bringing something unique and fresh. Reference the existing in-game version for likeness.
- why: Players buy the variant because they love the original; losing recognition loses them.
- apply: For any variant, list the base's identifying features (F09) and keep them; change theme, materials, colour. Reference the base model/images directly when making variant reference images.
- check: Side-by-side at game size with the base: does a reviewer recognise the same character instantly? Is the new theme obvious?
- mistake: Losing the likeness to the current in-game version (R03:980-984).
- example: Star Guardian, PsyOps as alternate-universe takes (R03:372-378).
- roblox_fit: Same for Roblox skins, pets and limited-time cosmetics [inference].

### R03-F19 Know when to stop
- principle: Over-rendering is real. A good stopping point: everything is rendered, all materials are clear at game height (golds read gold, not bronze or silver), the face is rendered to match the other game characters, and nothing looks incomplete when zoomed. ### R03-F22 Indicate hair, do not spell it

- mistake: Spelling out every strand, which slows you and adds noise (R03:548-552).

### R03-F34 Hue shift instead of white and black
- principle: To raise or lower value without muddy colour, shift the hue: some hues are naturally brighter (yellow, cyan) and some darker (purple). Shadows of a red coat go toward purple, highlights toward orange; it still reads as red. Value is brightness; hue is the colour itself.
- why: Multiple colours in one material add interest and keep it "fresh"; going to black or white kills saturation.
- apply: In materials, palettes, UI and VFX colour ramps: shadow = local colour shifted toward a darker hue (red→purple), highlight = shifted toward a brighter hue (red→orange); avoid pure black/white mixes. Image-model prompts can ask for "warm highlights, cool purple shadows" [inference].
- check: Sample shadow and highlight pixels on a material: hue differs from local colour by a visible step; saturation is kept; no greyed shadows.
- mistake: "always going towards white or black" for highlights and shadows (R03:758-762).
- example: Red velvet coat with purple shadows, orange highlights (R03:766-789).
