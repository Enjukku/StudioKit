## Will an agent with these books make better work?
Yes, clearly. I read the books as the qa-lead at the start of a feature job with a sell button and a slam ability (the skill has no evals; `proposals/qa-lead.md:28` asks for one). The old books gave it the engineering half: trace table, real data, oracles, planted faults, protected acceptance, verdict words, nothing about what players see. The new books keep all of that and make the agent collect the partners' sheets with revisions, ask the builder for named hooks at plan time, add a rejected-request row with the server log as oracle, a drawn-edge row on the data radius, a burst row, a reduced and grayscale row on the busiest moment at the smallest phone, a range read on every semantic layer, and end with what each input could and could not prove. The blocking defect of round 2 (ranges sent to the server `Seed`) is fixed correctly and agrees with the VFX and reviewer books. What is still weak is small: the range read does not say where to read a short-lived client effect or ask for a random-source seam (R1), the self-review tail sits near the compaction cut (R2), the paid-egg example lags its own §A rule (R3), and an old line sends rework records to the inbox (R4). The books are about 3.6 times the old size (21.8 KB to 79.2 KB with the role), but the growth is the new half of the job and sits mostly in `references/`, where each PF row is a test, not advice.
