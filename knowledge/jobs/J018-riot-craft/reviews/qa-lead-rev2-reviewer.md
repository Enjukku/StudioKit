## Will an agent with these books make better work?
Yes. I read the books as the qa-lead at the start of a feature job (a sell button and a slam ability; the skill has no evals). The old books gave it a strong engineering half: trace table, real data, oracles, planted faults, protected acceptance, verdict words. Nothing in them made it test what players see. The new books keep all of that and add a second half that is concrete and runnable: collect the partners' sheets with revisions, ask for named hooks at plan time, add a rejected-request row, a drawn-area row on the data field, a burst row, a reduced row and the busiest moment on the smallest phone, each with its oracle in data or the server log, and end with what each input could prove. The round 1 fixes are all in. The one remaining defect is QS-12: it sends the agent to the server `Seed` hook for decoration ranges that live in particle properties and client code, so the most likely result is a PASS that tested nothing. The weak spots after that are small: the camera line in the repetition row, the `Clarity` hook, spec-only pulse rates labelled as such, and an `evidence` key in the finding format. The books are about four times longer than before (14.6 KB to 63.7 KB), but the growth is the new half of the job, mostly in `references/`, and each PF row is a test, not advice.
