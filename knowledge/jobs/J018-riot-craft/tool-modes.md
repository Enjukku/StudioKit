A book names only modes listed here (or in the tool's own docstring). A check that needs a mode not listed is a manual check plus a proposal row for the tool. Before a book names a mode as a check, run it once on a sample of the input the check will really get.

## tools/art/art_refs.py
```text
usage: art_refs.py [-h] [--bible BIBLE] {print,run,approve} ...

Generate reference images with ChatGPT's image model, through Codex on the owner's ChatGPT subscription.

Kit tool (universal). Ported 2026-10-20 from DestructionSimulator tools/art/art_refs.py; the families and
locks now come from the game's art bible instead of being written in this file.

Every prompt = IDENTITY (the manifest row) + the family's lock + the world lock (unless the family skips it).
The locks and the family table live in knowledge/design/art-bible.md, so each lock has exactly one copy.
Up to three approved anchors from content/art/anchors/<folder>/ are attached to every call; `approve`
grows that library.

  python tools/art/art_refs.py print   <manifest.csv>             # assembled prompts, no generation
  python tools/art/art_refs.py run     <manifest.csv> [--limit N]  # generate missing rows
  python tools/art/art_refs.py approve <family> <id>               # copy a ref into the anchors
  --bible <path> (before the command) uses another art bible, e.g. the kit template for a quick test

Manifest columns: id, family, identity, inputs (optional; ';'-separated extra image paths attached before
the anchors), anchors (optional; ';'-separated file names in the family's anchor folder, or `none` for no anchors at all).
Every row runs in its own new Codex session (one image = one chat), so images never edit or copy each other.

Art bible format (machine-read):
  - a markdown table with the header `| family | lock | world lock | anchors |`; `world lock` is yes or no;
    `anchors` is the anchor folder name (empty = the family name);
  - fenced ```text blocks whose first words are `<NAME> LOCK:`; the world lock is `WORLD STYLE LOCK:`.

positional arguments:
  {print,run,approve}

options:
  -h, --help           show this help message and exit
  --bible BIBLE        art bible to read (default: knowledge/design/art-
                       bible.md)
```

## tools/vfx/clip_metrics.py
```text
(no --help; module docstring follows)
Measure what a recorded VFX clip shows, frame by frame, without AI taste.

Input: a capture folder of `f###_<ms>.jpg` frames (tools: the Studio capture rig).
Output: `metrics.json` in that folder: per frame screen coverage, bright coverage, box, centre,
mean colour and peak brightness of the pixels that differ from the background, plus a clip summary
(onset, peak, how long it stays visible). Used for frame scripts and the similarity score
(knowledge/reference/vfx/training/benchmark.md).

Background = per-pixel median of all frames, so it suits fixed-camera clips. Clips whose camera
moves (`_follow`) are measured anyway and flagged `moving_camera` in the summary.

Usage:
  python tools/vfx/clip_metrics.py <capture_dir> [<capture_dir> ...]
  python tools/vfx/clip_metrics.py --all output/vfx/training-captures
```

## tools/progression/sim.py
```text
usage: sim [-h] --policy
           {buy-next-in-order,cheapest-eligible,greedy-roi,save-for,fight-best,grind-to-level}
           [--mode {exact,float}] [--target TARGET]
           [--target-level TARGET_LEVEL] [--skill SKILL] [--sessions SESSIONS]
           [--seed SEED] [--runs RUNS] [--horizon-s HORIZON_S]
           [--soft-wall-s SOFT_WALL_S] [--soft-wall-ratio SOFT_WALL_RATIO]
           [--top TOP] [--max-events MAX_EVENTS] [--out OUT]
           [--trace-out TRACE_OUT] [--lean] [--lean-steps LEAN_STEPS]
           model

Progression simulator: plays one named model player (a policy) through a game's data tables (one JSON
model file) and reports the timeline - time to each goal in active and calendar time, soft and hard walls,
power spikes, blocked paths, the per-currency ledger and numeric precision flags.

positional arguments:
  model                 game model JSON

options:
  -h, --help            show this help message and exit
  --policy {buy-next-in-order,cheapest-eligible,greedy-roi,save-for,fight-best,grind-to-level}
  --mode {exact,float}
  --target TARGET       save-for: producer/item/enemy/activity id
  --target-level TARGET_LEVEL
                        grind-to-level: level to reach before bosses
  --skill SKILL         skill profile name from the model
  --sessions SESSIONS   session pattern name from the model
  --seed SEED
  --runs RUNS
  --horizon-s HORIZON_S
                        active-time horizon in seconds (overrides the model)
  --soft-wall-s SOFT_WALL_S
                        soft wall: minimum wait in active seconds
  --soft-wall-ratio SOFT_WALL_RATIO
                        soft wall: minimum multiple of the previous step's
                        wait
  --top TOP             rows in ranked lists (display only)
  --max-events MAX_EVENTS
  --out OUT             also write the report here
  --trace-out TRACE_OUT
                        write the event trace here instead of inline
  --lean                small report: no trace; steps only at resets, goals,
                        soft walls and spikes
  --lean-steps LEAN_STEPS
                        with --lean: also keep the first N steps in full
```
