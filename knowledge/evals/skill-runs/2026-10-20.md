# Skill eval run 2026-10-20: 9 engineering skills, 44 briefs

## Method

| Item | Value |
| --- | --- |
| Subject | One fresh subagent per brief. It read only `AGENTS.md`, the skill's `SKILL.md` and its `references/*`. No web, no Studio, no evals, no sibling skills, no rules, no overlay or game profile. |
| Brief text | Verbatim from `evals/briefs.md`. A `Setup:` line was given as true. |
| Score | Each must-pass bullet = one check. Clause failures inside one bullet count as a fail of the bullet. The runner scored from the subagent's written answer. |
| Fault line | Found by reading the cited skill text. Ids (D-04, N-09 ...) are the skill's own. No skill was edited. |
| Self-reported gaps | Each subject also listed what was unclear. Those gaps are used for the "weak" notes. |

## Cross-cutting findings (most useful first)

1. **Rules that live in a sibling skill are one pointer deep.** Failures in net E-02, ui E-01, arch E-03 and cr E-02 all come from a SKILL that says "see `data-saving`" or "see `platform-policy`" with no one-line rule. Real agents load siblings (AGENTS.md §2), so this is a weak link, not a proven defect. A one-line rule next to each pointer would remove four of the 11 failures.
2. **Buried lines.** N-09's remote rule (net E-05) and U-06's long-press clause (ui E-04) exist but were missed. Both sit at the end of long table cells. Put checkable rules in a short list in §3 or §6.
3. **No severity scale or report format in `code-review`.** All five code-review subjects invented HIGH/MEDIUM/LOW. All five also asked what to do when the intent is missing, and none had a rule for it. `V-11` says depth is quick/standard/deep but gives no criteria.
4. **No rule for "the brief conflicts with a rule".** Seen in platform-policy E-04, E-05, networking E-02/E-04, performance E-05, analytics E-02 and architecture E-04. All subjects pushed back and returned `needs-decision`, which was right, but each had to infer it from AGENTS.md. One shared line in AGENTS.md would cover all nine skills: build the compliant variant, name the rule, ask the owner to override.
5. **No triage for vague reports.** performance E-01/E-03, ui-basics E-03/E-04 and architecture E-02 are reports, not builds. Every subject invented its own first questions.
6. **Numbers that disagree.** testing.md "100 cycles" vs code-review E-03 "×20" vs `budgets.md` "20 cycles"; F-09 "10-15 min" vs the 20-minute memory brief; D-08 "errored" vs D-04 "degraded"; `budgets.md` 30 FPS floor vs 60 FPS in F-02; ui-effects "input accepted on press" vs U-07 `Activated` (release).
7. **Pointers to files the kit does not ship.** AGENTS.md says the context packet "arrives in kit phase 2". Every skill ends with "read `knowledge/overlays/<skill>.md` if it exists" and many cite `game-profile.md`. Many subjects asked what to do when those are missing. Say "skip if absent" once.
8. **Positive.** The refusal and push-back briefs passed: data-saving E-03/E-04, platform-policy E-03/E-05, performance E-05, networking E-04, analytics E-02, architecture E-04. The skills hold their strongest rules well. Every subject used the status words and the `PROPOSAL` rule from AGENTS.md.
