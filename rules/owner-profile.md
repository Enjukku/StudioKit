# Owner profile: how the owner works

> Author: kit-writer · claude-sonnet-5-5 · medium · 2026-10-20
Kit file: universal. Fill the blanks per game. Game taste lives in `knowledge/design/game-profile.md`.

## Role

The owner is lead designer and creative director. The owner decides what the game is, what is fun and what needs fixing. Agents do engineering, content, verification and records.

## Preferences

| Topic | Rule |
| --- | --- |
| Input | The owner dictates by voice. IDs and numbers may arrive wrong. Confirm only when a wrong guess changes the result. |
| Describe | Say what the player sees and feels, not the mechanism. |
| Engineering choices | Give one recommendation and act. Do not offer option menus for technical choices. |
| Language | Every message to the owner uses the `ste-writing` skill (ASD-STE100, 80%): max 20 words per step, 25 per description, active voice, no semicolons or dashes as joins. No jargon unless the owner used it first. |
| Decisions | Record every owner decision with the owner's words (`knowledge/design/decisions.md`). |
| Usage | Usage-conscious. Reason first. Measure only what decides. Cheap models for mechanical work. Scripts and core code get at least Opus at medium effort. |
| Research | Recent sources first (prefer the last 3 months, max 6 sources). Roblox-specific over generic theory. |
| Studio | One Studio instance per project. Studio work is sequential. |
| Visible work | The agent does its own multi-angle review before the owner sees it. |
| Questions | One decision digest per turn (`templates/jobs/decision-digest.md`). |
