# tools/audio/soundbench: the kit's audio editor for an agent

> Author: feature-builder · claude-opus-5-5 · high · 2026-10-23 (J020 steps 1-6; repair rounds 2 and 3); `generate` 2026-10-24 (step 7). Kit tool (universal). Design: `knowledge/jobs/J020-sound-workbench/editor-design.md`.

Built for an agent that cannot hear (J020-D2): text in, numbers and pictures out. Its first duty is to give right numbers and **never shift or damage a sound without an error**. Every number is a screening aid, never a taste verdict (G-4): the owner judges in play-tests (J020-D3).

Needs Python 3.11, numpy, scipy, soundfile, pyloudnorm, matplotlib, and ffmpeg (tested on 9.0.2). Only `generate` calls the network (ElevenLabs, standard library `urllib`); every other command is offline.

## Commands

`python -m tools.audio.soundbench <command>` from the repo root. Exit 0 done, 1 doctor found a missing item, 2 refused or failed (reason on stderr).

| Command | Does |
| --- | --- |
| `doctor [--root DIR] [--json]` | Python and libraries (FLAC in libsndfile, matplotlib Agg); ffmpeg found (`SOUNDBENCH_FFMPEG`, then PATH, then the WinGet folder) and how; its version (another version than 9.0.2 is a WARN: re-run the tests); the filters `afftdn`, `adeclick`, `rubberband`, `chorus`; the MP3 decoder; a live G-7 self-test (afftdn's lag measured and compensated to 0); the `ELEVENLABS_API_KEY` entry in `knowledge/design/keys.json` (the key file is only checked to exist, never opened) |
| `measure <file> [--low-cut HZ] [--high-pitch] [--json] [--picture PNG]` | F-01 to F-12 and the new measures (below); `--picture` writes a waveform + spectrogram PNG |
| `compare <a> <b> [--json]` | every measure of two files side by side with `b - a`, and the lag of b behind a (same rate only) |
| `parity <files> --mode integrated\|momentary [--json]` | F-13 loudness parity (integrated: options and siblings; momentary: paid random results) |
| `render <cue-folder> [--picture] [--json]` | applies `recipe.json` to the take (or its layers, or one take per variant; with a loop or seeded variants when the recipe asks: section below), exports FLAC, re-measures the delivered file against `card.json`, runs the paid-reveal family check. Exit 0 every must-target passed; 1 a must-target, the level or the family check failed (the file is still written, the report says why); 2 refused (also any malformed input or unexpected error); 3 a paid-reveal family is incomplete: re-render after the siblings |
| `rank <cue-folder> [--round K] [--picture] [--json]` | scores every take of one round (`takes/<cue>.r<k>.t<n>.mp3` or `.wav`, or a layered round's `takes/<cue>.<layer>.r<k>.t<n>`; the highest cue round unless `--round`; round 4 refused, J020-D7) against `card.json` (layers: against each layer's own targets in `recipe.json`), computes which misses the edit pass can fix, orders the takes and proves the top take's fix (layers: the mix of each layer's top take) with a real render on a temp copy (section below). Writes `report/<cue>.r<k>.rank.json` and `.md` only. Exit 0 the top take (layers: every layer and the mix) passes every must-target after its fixable steps; 1 no take does: regenerate with a changed prompt, or after round 3 the cue goes to the owner with its numbers, or the layers pass alone and their mix misses; 2 refused (bad input, a changed take, an inconsistent family, a round with plain and layer takes, or rank and render disagree) |
| `generate <cue-folder> [--budget CREDITS] [--dry-run] [--json]` | one round of ElevenLabs takes for the cue from `prompts.json` (section below). Run it through `python tools/keys.py run --only ELEVENLABS_API_KEY -- python -m tools.audio.soundbench generate ...`. Exit 0 every planned take made and decoded; 1 stopped by the budget or a take rejected; 2 refused before any call, or a call failed |

## A cue folder (design section 2)

`content/audio/<cue-id>/`: `card.json` (kind, category, tier, level with its measure, targets with `must` or aim, key, form, family, playback), `recipe.json` (the take and the two passes), `takes/<cue>.r<k>.t<n>.mp3` with its sidecar `.json` (the intake record) and `.master.wav`, and after `render`: `out/<cue>.flac`, `out/<cue>.log.json` (every step with its parameters, its numbers and a before/after snapshot), `report/<cue>.render.json` and `.md`, and pictures when a target misses, for important cues, or with `--picture`. The schemas with an example are in the `card.py` docstring; kinds and scales are data in `tables.json`.

## Operations (design section 4)

Design pass, in the SC-09 order clean > pitch > eq > compress > add > compress again > transient > air (a step out of order needs a `why`, otherwise refused):

| Stage | Operation | What it guarantees (tested) |
| --- | --- | --- |
| clean | `dc`, `highpass`, `lowpass` (RBJ biquads, order 2 or 4) | -3.01 dB at f0, the same curve as `scipy.signal.butter`; onset kept |
| clean | `denoise` (ffmpeg afftdn) | nf at most 3 dB above the take's measured tail floor (default: that floor; afftdn is absolute dBFS, so a fixed nf ate quiet takes); latency 1,102 / 1,200 samples compensated per channel; level, length above the floor, balance, attack share, main transient (1 ms), roughness kept |
| clean | `declick` (ffmpeg adeclick) | sustained and loop kinds only; latency 0; read with wrap/reflect context so its start-up ramp stays outside the sound |
| clean | `dehum` (50/60 Hz notches and harmonics), `gate` (tail floor; lookahead, so the attack is passed exactly) | hum down 30 dB or more; attack untouched |
| pitch | `varispeed` (scipy resample_poly) | pitch within 0.5 cent, length changes with it; the default for percussive takes |
| pitch | `pitch` and `stretch` (ffmpeg rubberband, `transients=smooth`) | sustained kinds only; pitch within 5 cents of the asked shift on a trusted note; its broadband level loss (0.4-4.3 dB measured) restored by gain, more than 6 dB refused; event positions (click probe, the audio, a stand-in of the kind) within 1 ms + 3 ms per semitone (pitch, at most 3 semitones) or 2 ms + 40 ms x abs(ratio - 1) (stretch, ratio 0.8-1.25: the measured shift is about 40 ms x abs(ratio - 1)); length x ratio; roughness rise at most 0.05 |
| pitch | `to_key` | refused when F-10 is untrusted; moves to the nearest note of the card's key |
| eq | `eq` (bell, low shelf, high shelf, notch) | the asked gain at f0 within 0.5 dB (the `sosfreqz` value within 0.05 dB); a boost over 6 dB needs a `why` |
| compress | `compress` (soft knee; threshold in dB below the input's own peak), `limit` (lookahead true-peak, absolute dBTP ceiling) | the static curve within 0.2 dB on a steady tone; a quiet take is compressed exactly as the same take normalised; the limiter holds the true-peak ceiling (x4) and reports its deepest reduction; on sfx and ui a transient cut over 0.5 dB needs a `why` |
| add | `space` (generated tail, RT60 at most 1.5 s: never a room, J020-D10), `echo`, `chorus` (ffmpeg, latency 0, its tail declared; the audio timed on its dry path, the full graph on the probe and a stand-in; decay at 0.9 x in_gain or more is refused at the parameter check: a wet copy as strong as the dry one cannot be timed) | the dry sound untouched before onset + predelay; RT60 within 20 %; echo exact |
| transient | `transient` (fast vs slow peak follower) | attack up raises the attack share; sustain down lowers the tail; a steady tone untouched |
| air | `saturate` (tanh soft clip relative to the input's own peak) | exactly its formula pk tanh(g x / pk) / tanh(g); a quiet take is saturated exactly as the same take normalised; logs the nonlinear residual over the whole file (`residual_db`) and over the body outside the peak +-10 ms (`residual_body_db`: the peak-relative drive hits a transient hard and the body hardly), and the phone loss before and after |

Edit pass, always in this order whatever the recipe lists (the log says when it reordered): `trim` (to the kind's onset binding: rising kinds to F-01, hits to the main transient, 1 ms preroll faded when not silent; a first sample above peak - 60 dB gets a 0.5 ms fade from sample 0, since 7 of 10 real takes started mid-waveform; it logs the first-sample level, the attack share before and after the fade and `lead_in_ms`; when the fade leaves under 90 % of the attack share it still fades (a click is worse) and logs `edge_fade_attack_loss`, and the card's attack targets decide) > `cut` (a cut through sound needs a fade-out of 5 ms or more) > `fade` (a fade-in that softens the attack needs a `why`) > `mono` > `loudness` (the card's own level measure: F-09, F-13a or LUFS-I for 0.4 s or more, within 0.05 dB) > `peak` (true-peak ceiling minus a 0.5 dB margin, by gain only, never a limiter) > `export` (FLAC).

Design-pass dynamics (`compress`, `saturate`, `gate`) are relative to the take's own peak, so a quiet take and a loud one are shaped the same; the edit pass sets the absolute level. The limiter's ceiling stays absolute: it is a delivery limit.

Every ffmpeg operation is guarded after it runs, in both directions where both are damage: F-09 within +-1.5 dB; the part of the sound 10 dB over its floor keeps 85 % of its length (x ratio for stretch); the channel balance within 1 dB; a sound with an attack (attack share 0.02 or more) keeps its share within 80-125 %, its rise within +-2 ms and its main transient within 1 ms. chorus changes level and envelope by design: it is guarded on timing and balance (2 dB) only. Channels that correlate 0.9 or more (real takes are often near-mono) are checked for a swap by level order only. The review-1 cases are refused: rubberband on a 400 ms hit, adeclick on a clean hit (even when mislabelled sustained); and the repair-round case: denoise nr 40 nf -20 on a take peaking at -36 dBFS (refused by the nf check and, without it, by the level guard).

`tools/audio/cue_check.py` still works with the same command line and output: it is a thin wrapper over `measures.py` (G-3).

## New measures (design section 5)

In `measure` output next to F-01..F-12. Known false readings are in each function's docstring in `measures.py`; the main ones:

| Key | Measure | Watch for |
| --- | --- | --- |
| `main_transient_ms` | first point of the 1 ms envelope within 10 dB of its maximum | a rising sound is late by design |
| `attack_rise_ms` | 10 % to 90 % of the 1 ms envelope | cannot read a rise under about 2 ms |
| `attack_share_5ms` | energy in the first 5 ms after F-01 / the F-12 sound's energy | a noise head moves the onset |
| `phone_loss_db` | dB lost through a 400 Hz high-pass and 10 kHz low-pass (4th order) | a rough phone model |
| `tail_noise` | floor after the F-12 sound (or the last 100 ms) and signal-to-noise | `sound_reaches_end` true: the floor is the sound itself |
| `clicks` | steps over 8x the local step RMS (±2 ms) and 1 % of the peak, every channel; `edges`: a first or last sample, as stored (before the mean is removed: playback starts from it), at 1 % of the peak or more (card target `edge_clicks`) | a hard edge from silence reads as a click; a click in loud noise hides; a loop's end edge is its seam |
| `tonality` | spectral flatness (tonal / mixed / noisy) and the notes present | harmonics are listed as notes |
| `roughness` | depth of 30-150 Hz envelope movement | two close notes beating read rough |
| lag (`compare`; the adapter per channel) | cross-correlation, mean removed | periodic, silent or inverted input reads "not clear" |

PROPOSAL values (start points a check may change; each is a named constant in its module): the click factor 8, the flatness limits 0.05 / 0.30, the lag limits (correlation 0.5, second peak under 90 %), the intake tolerance 10 ms, the latency tolerance 0 samples, the denoise nf margin 3 dB, the level guard 1.5 dB, the length keep 85 %, the balance 1 dB (chorus 2 dB), the channels-alike correlation 0.9, the rubberband loss limit 6 dB, the edge fade 0.5 ms, the chorus wet limit 0.9 x in_gain (measured: the probe first fails at 0.90), the saturate body window +-10 ms; rank: near-silent -60 dBFS, clipped 10 ms or more at or above -1 dBFS inside 300 ms, a missing band under a tenth of its minimum, the fix fade-out 10 ms, the cut 1 ms inside, the `near` margins in `tables.json` (a layer row `layer[<name>].<target>` uses its target's margin), the layered-round passes `LAYER_FRAME_PASSES` 4.

## Known limits

- **Speed on long files:** F-10 (moved unchanged from cue_check) finds its loudest 200 ms window with `np.convolve`, which grows with file length times window length: a 2-minute music bed takes minutes. F-09 now uses a cumulative sum over the same 400 ms windows (J020 step 5: the convolve was 97 % of a rank's time; the 55-case golden test passes and the old and new arithmetic differ by under 1e-13 dB on every fixture); the new measures use cumulative sums too. A faster F-10 needs the same golden check before it replaces the old arithmetic.
- **Lag on periodic sounds:** a steady tone or a loop correlates equally at every period, so its timing is proven on the probe signal, not on the audio itself (the log says so). That proves the graph's latency, not that this audio came out aligned.
- **Known latencies are measured per rate:** afftdn 1,102 samples at 44.1 kHz, 1,200 at 48 kHz on ffmpeg 9.0.2. Not a formula (22,050 Hz reads 550, not round(0.025 x rate) = 551): other rates and other filters are refused until measured and added to `KNOWN_LATENCY`.
- **Intake takes MP3 and PCM WAV.** ffprobe 9.0.2 states no start time for a PCM WAV; intake reads it as 0 (PCM has no encoder delay) and keeps every other check. An MP3 must still state its encoder delay.

- **rubberband is not sample-exact.** Even in smooth mode it moves events about 2.6-2.9 ms per semitone and about 40 ms x abs(ratio - 1) when stretching; the guards bound that (and refuse more), they cannot remove it. Hence sustained kinds only, pitch within 3 semitones and stretch within 0.8-1.25. Its default (crisp) mode put 12-27 % amplitude modulation and up to 9.5 cents of pitch error on a steady tone, so soundbench always uses `transients=smooth`.
- **Denoise on a noise-only sound** (a whoosh made of noise) can move its swell: afftdn cannot tell such a sound from noise; the main-transient guard refuses it when it does (17.7 ms on the quiet whoosh fixture at 44.1 kHz).
- **The compressor's detector ripples** on low tones: its static curve holds within 0.2 dB on a steady sine, not exactly.

## Ranking takes (`rank`, design section 6)

Every number in the rank table is a measure of `measures.py` scored by `render.evaluate` (the function `render` uses on the delivered file), so a reader can recompute it.

1. **Rejected outright** (no fix is claimed): clipped at the source (10 ms or more at or above -1 dBFS inside any 300 ms window of the decoded take: full scale, never the take's own peak, since the MP3 decoder overshoots above a clipped plateau; inside a window, never in total, since a total grows with the take's length. Calibrated on MP3-decoded copies at 128k and 192k: the 62 real takes as delivered read at most 7.23 ms, so the margin is 2.8 ms; 97 long clean fixtures built from them (each take x4, whooshes and notes slowed x4, crossfaded beds, chord pads of 2 s and 5 s) read at most 6.6 ms, except slowed full-scale rumble (86-99.97 % of the energy under 120 Hz, 2-3 of 97, up to 20 ms: a steady tone at full scale reads clipped). Hard-clipped copies caught at 128k / 192k: short +12 dB 37 / 38 of 62, +6 dB 24 / 24, +3 dB 15 / 15; long +12 dB 24 / 25 of 26, +6 dB 21 / 22, +3 dB 14 / 16. Sustained takes are caught; **short hits are not caught even at +12 dB**: their clipped tips last under a millisecond each and the MP3 smears them. No real ElevenLabs take of 2 s or more was available: the long fixtures are built from 480-800 ms real takes); near-silent (sample peak under -60 dBFS; the quietest real take peaks at -43.9); no sound in a band the card needs (a `must` band share under a tenth of its minimum).
2. **Each target scored**: `inside`, `near` (inside but within the `near` margin in `tables.json`; still a pass, as render counts it) or `miss`, with `miss_by` (how far outside) or `margin` (how far inside).
3. **Fixable is computed, never guessed.** The edit-pass steps for the take's misses (a late onset or main transient, or a click at the start edge: `trim`; sound or file too long: `cut` 1 ms inside the maximum with a 10 ms fade-out, planned on the audio after `trim`, since trimming moves the length; a click at the end edge: `fade`; `mono`; then `loudness` and `peak` whenever any step runs, `peak`'s ceiling the lowest of -1.0, the card's true-peak max and its sample-peak max) are run through render's own step loop (`render.apply_steps`), measured again and scored again. **Three plans are scored**: every miss, the must misses only, and no step; the fewest must misses after it wins, then the fewest aim misses, then the order all > must > none. So an aim fix that breaks a must (the level reset after a trim, on a take whose true peak sits between the peak limit and the card's max) never turns a usable take into a regenerate; the aim fixes left out are reported. A plan an operation refuses (a cut that leaves LUFS-I under 0.4 s) is recorded and its reason is written into every miss it leaves. Every plan's result also goes through `export.check_exportable`, the same function `render`'s export calls, so a kept plan is always one render can deliver: a master over full scale gets `loudness` and `peak` (its no-step plan is refused with export's reason), and a take render cannot export at all (over 48 kHz) has every plan refused and does not pass. A miss counts as fixed only when its re-measured row passes; a row the fix itself breaks is listed under `introduced`. Anything no edit-pass step moves (bands, phone loss, flatness, attack, key, too short or too early) is a prompt miss: rank does not compute design steps.
4. **The level is derived as well as simulated** (review-1 #9: `peak` is gain only, sfx and ui do not limit transients): `gain_needed` = the gain `loudness` applied (the ratio of the peaks; for F-09 it is `target - level_in`, for F-13a and LUFS-I on a quiet take it is not, because the -70 LUFS absolute gate moves blocks as the gain changes), `peak_limit = min(-1.0, card true_peak max, card sample_peak max) - 0.5`, `headroom = peak_limit - true_peak_in`, `peak_cut = max(0, true_peak_in + gain_needed - peak_limit)`, `predicted = level after loudness - peak_cut`; it fits when `|predicted - target| <= tolerance`. The derived and the simulated level must agree within 0.1 dB, or rank refuses (exit 2). A take too loud always fits. For music, ambience and voice the reason adds that a `limit` design step could make room (not computed).
5. **Order** (`rank_key`): rejected last; then a take that passes after its fix before one that does not; then fewest must-misses after the fix, fewest aim-misses after it, fewest misses that needed a fix, fewest near readings, the take number. A must-miss never ranks above a pass.
6. **Proof** (only when the top take passes: a round where no take passes is regenerate, exit 1, never a refusal): the top take's fix recipe (empty design pass) is rendered for real on a temp copy of the cue (hash checks, parameter checks, edit pass, FLAC export, the delivered file measured again); every target row must match the simulation (values within 0.02 or 0.2 %), or rank refuses. The copy is removed; rank never writes `out/` or `<family-id>.family.json`.
7. **Verdict**: `use` (the top take and its edit steps, a start for `recipe.json`), `regenerate` (round 1 or 2: the targets still missed after the fix, how many takes miss each, the closest value and its direction) or `owner` (round 3, J020-D7). Takes per round other than minor 3, frequent 4, important 6 (J020-D9) is a warning.
8. **Pictures** (light-check rule): the top take before and after its fix when an after-fix row misses or reads near, or for an important cue; `--picture` draws every take.

Paid-reveal families: rank refuses an inconsistent family declaration exactly as `render` does (exit 2) and never checks or writes D-03 state; `render` still runs F-13 b and the F-03 1 dB check on every member's delivered file.

**Layered rounds** (important cues; `generate` writes each layer's takes as `takes/<cue>.<layer>.r<k>.t<n>`, all at the cue round):

1. **The round** is the cue round: the highest round of the plain takes and of every layer (rounds are counted per cue, never per layer, J020-D7), or `--round`. A round that holds plain takes and layer takes is refused (exit 2). A plain round is ranked as above, whatever layer takes other rounds hold.
2. **The layers** come from `recipe.json`'s `layers` (names, each layer's own `targets`, its placement: `offset_ms` or `align`, `gain_db`, fades), where render reads them; the card has no layer list. It goes through render's own checks, so an important cue's layer without targets is refused with render's message. Every layer with takes in the round must be named there (refused otherwise), and every named layer needs takes in the round or before: a layer with none in round k is read from its latest earlier round (a round may regenerate only the layers that had no passing take; a warning says so). rank judges **recipe.json as written** (review-rank-layers F1): each layer's design pass, its placement, the mix design pass, the loop and the variants all stay; only the layer `take` fields and the `edit` pass are rank's (the recipe's own edit pass is not read; a warning says so).
3. **Each layer take** is G-1 checked and placed alone through render's own `mix_layers` (its own design pass, gain, fades, the layer edge fade, offset or align with its correction); a take render cannot place or design (its transient after the marker, a step refused on it) is rejected with render's reason. Its rows are render's `layer_rows` (`layer[<name>].<target>` and `layer[<name>].edge_clicks`), read on the layer as placed **in the mix it would make with the other layers' chosen takes**: render reads a layer's rows at the mix's length, and the length moves them (on real takes with 600 ms more silence: a hit's `sound_ms` 274.6 -> 294.1 ms, `tail_snr_db` 38.6 -> 46.0, band shares, edge clicks). Pass 1 reads each take at its own length; each next pass with the other layers' tops, until the tops stay the same (2 passes on every round so far; `LAYER_FRAME_PASSES` 4, then refused). Rejection is the one-shot rule (clipped, near-silent, no sound in a band the layer must have). A layer has no edit pass of its own (render runs trim, cut, fade, loudness and peak on the mix), so a layer take has no fix plan: its misses are prompt misses, with that reason. The order is `rank_key`.
4. **The mix**: when every layer has a passing take, the top takes are mixed by `mix_layers`, then the recipe's mix design pass and its loop run (render's order), and the result is judged as a one-shot take is (`judge`: the card's whole-cue rows, the three plans, the peak ceiling, the level derivation; no rejection). A recipe with a `loop` gets no trim, cut or fade in any plan (render refuses them across the seam, review-rank-layers F3): the level steps only, and a miss only those would fix says "a loop recipe has no trim ...: choose the loop's region in recipe.json's loop". Its layer rows must equal the ranked ones value for value, or rank refuses (exit 2).
5. **Verdict**: `use` (exit 0): every layer passes and the mix passes every must after its fixable steps; the chosen takes, `recipe` (recipe.json with those takes and the mix's edit steps, everything else as written), `recipe_layers` (its layers, design steps included) and `recipe_edit`, proven by a real render of `recipe` on a temp copy (every layer row compared, and every whole-cue row when there are no variants). `use` needs that render to fail no must row at all: a loop row (`form.loop_*`), the variant count or spread, or a variant file's row that render fails turns the verdict into `mix_misses` naming render's rows (review-rank-layers R2-1; the one-shot proof, which has no loop or variants step, still only notes form rows). `mix_misses` (exit 1, as render exits on that recipe): "the layers pass alone; the mix misses level ...": change the placement or gains in recipe.json, add a design step, or try a runner-up passing take (listed); rank judges one mix, each layer's best take, and tries no other combination. `regenerate` (round 1-2) or `owner` (round 3; counted as `generate` counts, by `generate.cue_rounds`: rejected and renamed rounds included, review-rank-layers F2; one-shot rounds too), exit 1: the layers without a passing take, each with the misses its prompt must change; the layers that pass are named to keep.
6. **Report**: one section per layer (its targets, placement, order table and each take's rows), then the mix (placement, shares, interference, headroom, its whole-cue rows and fix) and the proof. Pictures: each layer's top take, and the mix before and after its fix.

Real layered rounds (`test_rank_layered_real_rounds`, 12 real hit and thump rounds as the body layer over the first whoosh's takes, under F-09 and LUFS-I: 24 rounds): 6 `use`, 16 `mix_misses` (all on the level: `peak` is gain only and the summed layers' true peak caps the loudness gain), 2 `regenerate` (the body layer); render of each choice gives exactly the ranked layer rows and the same exit code.

Known limits: rank computes edit-pass fixes only, so a miss an `eq` or `limit` design step could close reads as a prompt miss (the sound designer may still try it; `render` measures the result). The clip check cannot see clipping that was scaled down after it happened, clipping under full scale (a ceiling at -0.9 dBFS was caught on 1 of 9 copies), or a clipped short hit after MP3 (not caught even at +12 dB), and a steady tone or slow low rumble normalised to full scale can read clipped. A clipped hit that passes rank reads as a level miss at most (`peak` cannot repair distortion): the owner's play-test is the check.

## Layers, loops and variants (design section 4, build step 6)

`assemble.py` holds the parameters and the numpy work; `render` runs them, in this order: source(s) > each layer's own design pass > mix > the recipe's `design` (on the mix) > loop > each variant > the edit pass > export. Recipe fields: the `card.py` docstring. Every step is logged with before/after numbers (G-2); every new reading is in the render report.

| Operation | What it guarantees (tested) | Rows it adds to `form_checks` (all must) |
| --- | --- | --- |
| `layers` | each take G-1 checked; a layer at another rate resampled to the first layer's rate on load (`resample_poly`, exact rational ratio, zero phase: events within one sample), with a `resample` step in the log; a layer lands at round(offset_ms x rate / 1000) samples on each of its own channels (a mono layer on every channel of a stereo mix); `align` puts its main transient (or F-01) on the marker sample: a first reading on the layer after 2 ms of silence (a take loud at its first sample read 0.84 ms later alone), then one correction by the reading of the layer as placed, the same reading the log shows (`align_correction_samples`); both readings are one function (`assemble.layer_index`): the layer's own audio with its own mean removed, on a copy, laid alone in silence (no other layer and no mix mean can move it); DC is removed for the reading only, never from the delivered audio (logged as `reading_dc`; an automatic `dc` step in round 1 added edge clicks to layers that fade to 0); a layer still more than one sample off after the correction is flagged `align_unstable`; a negative offset is refused; `fade_in_ms` / `fade_out_ms` per layer for splices; each layer's ends get trim's own hot-edge fade (`ops.fade_hot_edges`: 0.5 ms when the edge sample is over peak - 60 dB, logged per layer as `edge_fade` with the attack share before and after and `edge_fade_attack_loss`), so a take that starts or ends mid-waveform does not click inside the mix (9 real three-take sets: 0 clicks, from 7 before); the mix is as long as the latest layer end. Logged per layer: offset in samples and ms, F-01, main transient and F-09 measured on the placed layer, `share_energy` (its energy / all layers' energy), `share_of_mix` (its projection on the mix: they add to 1, negative = it cancels) and the mix's `interference_db` (0 independent, + in phase, - cancelling); `headroom`: the mix's sample and true peak, the loudest layer's peak and export's own check (`export.check_exportable`) on the mix: a mix past full scale with no design step, `loudness` or `peak` after it is refused before the edit pass | `layer[<name>].<target>`: each layer's own targets, measured on the layer as placed (alone); `layer[<name>].edge_clicks`: the clicks within 1 ms of the layer's edges as placed (max 0; must for important cues, aim for the others). An important cue's layers must each have targets (refused otherwise) |
| `loop_bed`, `loop_music` | the file is x[s : s+n] whose last `crossfade` samples fade into x[s-L : s]: its last sample is x[s-1] and its first x[s], exactly (a pair of neighbouring source samples), and the FLAC read-back keeps them within one 24-bit step; `loop_bed` takes `start_ms` (default: the crossfade), `end_ms` (default: the end) and `search_ms` (moves the end to the best-matching point); `loop_music` takes the downbeat `start_ms`, `bpm`, `bars`, `beats_per_bar`: n = the bar length rounded to a whole sample, the drift logged per loop and per 10 minutes; `curve` auto: equal power, or equal gain when the two crossfaded parts correlate at sqrt(2) - 1 or more. Refused: a card without `form.loop`, `trim` / `cut` / `fade` in the edit pass, a crossfade over half the loop, a start under the crossfade, an end past the sound, variants of a loop | on every `form.loop` card, with or without a loop step: `form.loop_f08` (F-08 at most R-26's 2; a card's `loop_seam` max only tightens it, and loosens it only as `must: true` with a `why`, logged in `limit_from`; an aim target never lifts it), `form.loop_wrap_clicks` (the click count within 1 ms of the wrap, the file rotated so the wrap sits inside it), `form.loop_wrap_hf` (the wrap's 2 ms second-difference energy at most 3 dB over the loop's own 99th percentile), `form.loop_seam_gap` (the seam's quietest 50 ms at most 6 dB under the loop's own 5th percentile); with a loop step: `form.loop_crossfade_level` (the crossfade at most 2 dB outside the band between its two parts' own levels, both ways), and for `loop_music` `form.loop_length_samples` |
| `variants`, `takes` | `variants`: n files (n = `card.form.variants`) from one sound, each `varispeed` by a seeded stratified draw in +-`max_cents` (at most the kind's `variant_max_cents` in `tables.json`, 30 with a key) and a level offset on the loudness target, drawn in +-`max_db` (at most 1 dB, R-31), then moved to the set's mean and scaled down until every offset (rounded to 0.01 dB) is within `max_db` of that mean (`assemble.centre_gains`: R-31's row reads each file against the set's mean, so the plan alone can no longer fail it; checked with render's row over 2-16 variants x 300 seeds; review-rank-layers round 2; the files of an earlier render with the same seed now differ); the same seed gives the same files (G-1, two processes); `takes`: one file per take through the same recipe. Files `out/<cue>-v<k>.flac`; files of an earlier render's other form or count are removed. Refused (exit 2) for tell, warning and countdown (SC-12), and when the count differs from the card's. The report notes S-92: the pitch is varied in the files, so no runtime PlaybackSpeed jitter on top | `form.variants` (the file count equals the card's), `variants.level_spread` (F-09 within +-1 dB of the set's mean, R-31). Each variant gets the card's rows, named `<cue>-v<k>:<target>` in `must_failed` |

Paid-reveal families: a member's delivered files are every file its card asks for (`out/<cue>.flac`, or `out/<cue>-v1..vn.flac`), so F-13 b and the F-03 1 dB check run across every variant of every member; a member with a variant missing is incomplete (exit 3).

Rank is unchanged: the card's rows stay in `targets` (what `rank` simulates and its proof compares) and the new rows go in `form_checks`. So `rank` judges a loop or variant card's takes as one-shots: a take it calls `use` can still fail render's loop rows; when its proof render shows such rows, the `use` text adds "form rows (loop, variants) are judged at render: <rows>" (verdict and exit code unchanged). Follow-up: rank scores loop cards after the recipe's loop step.

PROPOSAL values (named constants): `assemble.MAX_LAYERS` 8, layer gain -48..+12 dB, `CROSSFADE_MAX_SHARE` 0.5, `VARIANT_MAX_COUNT` 16, `VARIANT_KEYED_MAX_CENTS` 30, the kinds' `variant_max_cents` (hits, whooshes, beds 100; pickups, chimes, stingers, voice, music loops 30); `render.LOOP_F08_MUST_MAX` 2 (R-26), `LOOP_WRAP_HF_DB` 3, `LOOP_GAP_DB` 6, `LOOP_CROSSFADE_DB` 2; `measures.LOOP_WINDOW_S` 50 ms, `LOOP_MIN_BODY_WINDOWS` 8, `WRAP_CLICK_S` 1 ms.

Calibration (2026-10-23; 20 synthetic beds of 2-30 s: steady and swelling noise, a steady tone, a tonal pad, a bed spliced from realistic takes slowed x4; and 9 beds spliced from the 62 real takes slowed x4; each read at its seam and at 40 natural positions, 1,160 in all): good loops read F-08 at most 1.07, `wrap_hf_db` at most -1.2, a gap of at most -0.38 dB, a crossfade level of -1.67 to +0.63 dB. Natural positions over a limit: F-08 2 of 1,160, `wrap_hf_db` 2 of 1,160 (both natural transients in real-take beds), the gap 23 of 1,160 (all in beds with near-silent lulls). Planted faults: a spike 3 samples before the end of 0.25 x peak in tonal and spliced beds and 0.5 x peak in noise beds is caught by the wrap rows (F-08 does not see it); a drift jump of 0.3 x peak on tonal and spliced beds by F-08; a fade to silence of 100 ms at both ends by the gap row on 19 of 20 continuous beds; equal gain on noise reads -1.7 to -3.1 dB and equal power on a tone +2.6 to +3.0. Known limits: beds with a loud section: a seam jump under the click floor is not caught (F-08 and `wrap_hf` read the seam against the whole loop; a jump the size of the wind's RMS in a wind bed with rain over half the loop passes every row, 12 dB more is caught by the click count; pinned by a test, review step 6 R1); a 0.25 x peak spike inside low-passed noise reads like the noise's own top 1 % and is not caught (nor would `clicks` catch it inside the file); a fade gap on a bed that already holds near-silent lulls reads 0 (0 of 9 real-take beds caught); a slope break with no jump is not read; the seam is sample-exact in the file, but how Roblox's transcode treats the loop point is not measured.

## Generating takes (`generate`, design sections 3 and 8, build step 7)

Input: the cue folder's `card.json` (its tier sets the takes per round: minor 3, frequent 4, important 6, J020-D9) and `prompts.json`, written by the sound designer for each round (schema in the `generate.py` docstring): `prompts` (the takes are spread over them in turn), optional `duration_s` (0.5-30; left out, the service chooses the length), `prompt_influence`, `loop`, `model` (`eleven_text_to_sound_v2` default, or `v3`), `takes` (another count than the tier's is a warning), `note`. An important cue may give `layers` instead, one prompt set each, generated separately as `<cue>.<layer>.r<k>.t<n>`; they share the cue round (rounds are counted per cue, never per layer: J020-D7, review F5).

| Rule | What the tool does (tested with a fake HTTP layer; planted faults in `test_soundbench_generate.py`) |
| --- | --- |
| The key | read from `ELEVENLABS_API_KEY` only, sent only as the `xi-api-key` header; every text written or printed passes `redact` (the key and anything shaped like `sk_` + 16 or more characters become `<redacted>`); a sidecar keeps only the named trace headers (`character-cost`, `content-type`, `date`, `x-trace-id`, `request-id`, `history-item-id`, `x-region`, `retry-after`). A value already set in the Windows environment wins over the file in `keys.json`: an auth error says so. Redirects are never followed (a 3xx stops the run, exit 2), so the key header goes to no other host; an error body is redacted whole, then cut to 600 characters |
| Rounds | counted per cue (lead decision on J020-D7, review F5): the cue round is the highest round of any file of the cue or of any of its layers, under any name, kept or in `takes/rejected/`; every sound of the run (the take or each layer, new or renamed) gets that round + 1; round 4 of the cue is refused before any call; every sidecar and the run log carry `cue_round`. A round whose calls all failed made no file and is not used up |
| Credits | predicted per call: ceil(11 x `duration_s`), 55 without a duration (measured 2026-10-24); a round predicted over `--budget` (default 300, PROPOSAL) is refused before any call; before every call and every retry it stops (exit 1) when spent + possibly spent + the prediction would pass the budget. Each sidecar holds `credits` (the `character-cost` header), `credits_predicted` and `credits_all_attempts` |
| Formats | `wav_44100`, then `mp3_44100_192`, then `mp3_44100_128`: the next one only when a response refuses the format (a 4xx naming `output_format` or the format, or a 403 naming the subscription or tier), and a refused format is skipped for the rest of the run. The received bytes decide the file type (RIFF WAV or MP3); a mismatch is a warning; other bytes go to `takes/rejected/` |
| Errors | 429, 500, 502, 503, 504 and network failures retried at most 3 times per take and format (waits: Retry-After up to 30 s, else 2 s and 4 s); every attempt is in the sidecar or the run log with its status and charge: `yes` (a `character-cost` over 0, also on an error), `no`, `unknown` (no whole answer, including a body cut short after a 200 (`http.client.HTTPException`), or a 5xx with no `character-cost`: counted at the header cost when headers arrived, else at the prediction, as possibly spent; a 429 stays `no`). Any other answer stops the run (exit 2) with its status and body. A failed call writes no take |
| Files | one run per cue: `<cue-folder>/.generate.lock` is created exclusively before the first call (a held lock refuses, exit 2; a crashed run leaves it: delete it once no run is going) and removed on every exit path; ffmpeg and ffprobe are found before the first call (exit 2 otherwise). `takes/<sound>.r<k>.t<n>.wav` or `.mp3` and its sidecar `.json`, never over an existing file (checked before any call; a path taken during the call keeps the paid bytes in `takes/rejected/` under a fresh `.kept<n>` name, logged); then `intake.decode_take(take, requested_ms=)` once; a take intake refuses moves to `takes/rejected/` with its sidecar (its credits stay counted). Run log, written on every exit path once the lock is taken: `report/<cue>.generate.<UTC time>.json` (plan, attempts, credits predicted, spent and possibly spent, formats refused, warnings, why it stopped) |

Sidecar fields: `cue`, `sound`, `layer`, `round`, `take`, `request` (the exact JSON body), `query` (`output_format`), `format_asked`, `formats_refused`, `format_used`, `format_received` (container; for WAV the codec, rate, channels, frames from its header), `requested_ms`, `credits`, `credits_predicted`, `credits_all_attempts`, `response` (status, trace headers), `attempts`, `bytes`, `sha256`, `generated` (UTC), `note`, `status` (not auditioned), then `intake` (written by intake).

Measured on this kit's test key (Creator tier, 2026-10-24): every WAV and PCM format asked was given (44.1 and 48 kHz, looping too), so the MP3 fallback has not run against a real refusal; 0.1 s is refused (400 `invalid_generation_settings`, minimum 0.5); a 0.5 s request returns 480 ms (WAV and MP3 alike, logged by intake as a warning); a 1.0 s looping request returned 1.5 s. The live check is `test_soundbench_generate.LiveTest` (about 18 credits), which runs only with `SOUNDBENCH_LIVE_GENERATE=1` and a key, never in the gate.

PROPOSAL values (named constants in `generate.py`): `DEFAULT_BUDGET` 300, `MAX_ATTEMPTS` 3, `BACKOFF_S` 2 and 4 s, `MAX_WAIT_S` 30 s, `TIMEOUT_S` 120 s, takes per prompt set at most 12. Measured values: `CREDITS_PER_SECOND` 11, `CREDITS_NO_DURATION` 55, `DURATION_MIN_S` 0.5.
